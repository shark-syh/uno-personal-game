## 4. 座位椭圆锚点表与泛化

### 4.1 公式与不变量

- 圆心 = 竞技场中心 `(50%, 50%)`；锚点百分比相对**竞技场盒**：`--seat-x = 50% + 46% × cos(θ)`、`--seat-y = 50% + 40% × sin(θ)`（JS 计算，CSS 只消费，与 v2.0.0 相同）。
- CSS 角度约定 `0°=右、90°=下`；**真人固定在下方且不占对手位**（不渲染 `.opponent`）。**口径校准**：任务书写的「真人固定 270°」来自「0°=上、顺时针」的另一种约定；按本契约的生产公式（CSS 0°=右、90°=下），下方 = **90°**（`y = 50% + 40% = 90%`）。两种写法指同一视觉位置，实现与断言一律以 `--seat-y ≈ 90%` 为准，`players.js` 里不要把 270 写进对手表。
- 对手数 `N = players.length − 1`，相对座位 `i = 1..N` 从玩家左侧起顺时针。
- `data-seat` 保留真实座位号；`data-relative-seat` 用于布局与测试；`relativeSeat = (seat − viewer + total) % total` 逻辑保持不变（联机换座后视角正确）。
- CSS clamp 继续用：`left ∈ [--v2-seat-w/2 + 8px, 100% − --v2-seat-w/2 − 8px]`，`top ∈ [--v2-seat-h/2 + 6px, 100% − --v2-seat-h/2 − 6px]`；座位不得覆盖中心牌安全区（中心牌 ± 半宽/半高 +16px）。
- 座位内部信息顺序不变：头像 → 姓名 → N 张/UNO → 卡背扇 → `lastPlayed` → 当前回合描边；**DEMO 的 `.fan` 仅视觉，底部仍以 v2.1 M2 的 `.opponent-hand` 为准**（`aria-hidden`、`data-visible`、`data-overflow`、`.is-full` 全部保留）。**2026-10-26 用户反馈修订**：`.opponent-hand-overflow`「+N」徽标从卡背扇右上角移到**右下角**（`right:-2px; bottom:-2px`，允许下探座位框 ≤12px），不得遮挡头像/姓名/张数；verify-ui 新增「徽标不遮挡头像」断言（152 项基线）。

### 4.5 验算方法（Lead 在 N2/N4 用浏览器实测时照此复核）

1. 取竞技场盒 `getBoundingClientRect()`（宽 W、高 H）、`--v2-seat-w/h` 计算值；按 §4.1 公式算每个相对座位的中心 `(x,y)`（百分比 × W/H），再做 CSS clamp。
2. 每座位取 AABB：`[x−w/2, y−h/2, x+w/2, y+h/2]`；两两计算 `gap = max(|dx| − w, |dy| − h)`。判定：非矮屏桌面档（≥1024 宽、>800 高）`gap ≥ 6px`；矮屏档（≤800 高，含 1024×600/768、1366×657、1280×720）要求 `gap > 2px`（与现有 `verify-ui` 的 2px 容差不重叠判据一致；10 人局 1024×600 的 4.8px 为最低值）；移动端文档流 `gap > 2px`。
3. 中心牌安全区：中心 `(W/2, 0.46H)`，半宽/半高 = 中心牌实测尺寸/2 + 16px；任何座位 AABB 不得与其相交（现有 `layoutProbe` 的 `overlapCenter` 判据为 `#discard-pile` ±2px，契约取更严格的 ±16px）。
4. 座位 AABB 必须整体落在竞技场盒内（`0 ≤ left`、`right ≤ W`、`top ≥ 0`、`bottom ≤ H`）。
5. 一屏复核：`document.documentElement.scrollHeight ≤ clientHeight + 2`、`#hand` 与 `#action-bar` 的 `getBoundingClientRect().bottom ≤ innerHeight`。
