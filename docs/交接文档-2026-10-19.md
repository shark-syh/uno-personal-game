## 3. 引擎 / AI / UI 关键约定（违反会回归）

- 纯函数 reducer `applyAction(state, action) → { state, events }`（内部 structuredClone）；`state.events` 只本次、`state.history` 全量；seed 可复现；全牌恒 108 张。
- 堆方向：`drawPile` / `discardPile` **数组末尾是堆顶**（抽牌用 `pop()`）。
- 相位：`await-play` / `choose-color` / `stack-response` / `challenge-decide` / `uno-window` / `round-end`；`getLegalActions` 只给当前玩家。
- 摸牌：DRAW **一次摸 1 张**；摸到 `isPlayable` 的牌才设 `drawnThisTurn`（否则保持 null，可继续摸）；牌堆耗尽按 4.9 结算（不 advanceTurn）；事件顺序 `…PILE_RESHUFFLE → DRAW → ROUND_END`。
- 叠牌（loose）：+2/+4 任意互叠；单张 +4 链弃权 → `challenge-decide`；链中 +4 不开放挑战；最后一张 +2/+4 立即获胜。
- UNO：`uno-window` + `unoWindow.pendingPhase`；除 CALL/CATCH 外任何动作先关窗口；AI 喊/抓概率按 `aiDifficulty`；窗口 4s（`?test=1` 120ms）。
- 牌堆耗尽：默认 `reshuffle`，`end-by-fewest` 可配；并列最少 → 平局。
- 结算：`getResult(state, { durationMs })`，仅 `phase==='round-end'` 可调用；**统计全部由 history 汇总，不做分数**。
- **`packages/game-core/src/public-view.ts` 是 UI 唯一数据出口**（getGameView/toUiAction/toEngineAction/toPublicResult/createLobbyView），隐藏信息过滤都在这里；UI 不写规则。**M8 的服务端隔离也复用此文件**。
- 挑战手牌展示：见 §0 红线行。
- 规则设置仅对**新开对局**生效；`?test=1` 下引擎注入 `window.__unoEngineConfig` 供自动化断言（正常入口不写入）。
- 事件动效由 `animation/queue.js` 串行驱动，`effects.js` 只创建临时节点（`#effect-layer`）并返回时长；队列结束/被打断/切屏时 `cleanupEffects()` 兜底清理。
- 音效：`sound=false` 时不创建 AudioContext；`soundVolume` 0~1；自动化用 `data-audio` / `data-sfx-count` 观测。
- 浏览器前端零构建：TS 引擎 + AI 用 esbuild 打包为 `apps/web/js/vendor/uno-engine.js`；**改 packages 后必须 `npm run build:web-engine`**（`apps/server/tests/web-engine-bundle.test.ts` 会校验同步）。
- 默认入口 = 引擎模式真实对局（`?mock=1` mock、`?test=1` 快速）；大厅选项（人数/难度/+4 挑战/AI 模式）→ `GameConfig`。
- 自对弈：`npm run selfplay` 700 局（难度胜率单调 + 混战名次单调，含 2% / 0.15 容差）；逐张摸牌后平均回合约 60~160。

## 4. 高价值坑位（避免重复踩）

1. 改 `packages/game-core|ai` 后不 `npm run build:web-engine` → 浏览器跑旧引擎且 bundle 同步测试失败。
2. `verify:ui` 需服务已运行；固定调试端口 **9333**（`UNO_DEBUG_PORT` 可覆盖）；同时只能跑一个；现有 **103 项**检查，约 5 分钟。
3. `verify-ui.mjs` 的 `autoStep` 优先点 `#hand .card.is-legal`（操作栏已无出牌按钮）；等人类回合要 `!busy && humanReady()`；对局可能先结束 → 脚本已处理「结算页直接回大厅」分支。
4. `perf-check.mjs` 走 CDP，且**必须连 page target**（`/json/list`）而不是浏览器端点（`/json/version`），否则 `Page`/`Runtime` 域不可用。
5. 起手翻开 +2 时首位玩家手牌可能 9 张：等手牌数用 `>= 7`（不要写死 7）；卡面异步解码，统计前要等。
6. DRAW 事件可能 `count>1`（效果摸牌）；他人视角 `cards=[]` 但保留 `count`；UI 事件文案要用 `count`。
7. AI 台词 TTL 到期只清 DOM 文本，**不要整页 render**（会关闭玩家弹窗 / 打断事件动画）；所有定时器纳入 `rt.timers`。
8. 结算页**没有任何分数**；改 `result.js` 要保留图表数据属性（见 §2），否则 `verify:ui` 图表断言失败。
9. 不要在 UI 里算规则 / 分数；结算是引擎数据出口，UI 只展示。
10. 智谱 `glm-4.7-flash` 是思考型：必须 `thinking:{type:'disabled'}` 且 `max_tokens≥512`；429/1305 自动重试降级；Key 不落日志。
11. 弹窗 `source="auto"` 用于 UNO/抓人/选色/挑战；拖动重绘只关自动弹窗，玩家弹窗要保留。
12. 改静态资源后浏览器 `Ctrl+F5`；Windows git 已设 `core.autocrlf=false`，不要开 autocrlf。
13. PowerShell 不要用 `$home` / `$error` 等自动变量；命令在项目根执行。
14. 文档统一在 `docs/`，根目录只保留 `README.md`。
15. `mockView.js` 的 result 数据已带操作统计（无分数）；加 mock 局面时保持该形状。
16. `?test=1` 时 AI 延迟 15ms、UNO 窗口 120ms；自动化用它。

## 6. M8 概览（本地联机 + 用户隔离，待指令）

- **目标**：把「1 真人 + N AI」扩展为「**局域网内多名真人 + 补位 AI**」，并保证**用户隔离**——任何客户端都拿不到他人手牌与隐藏信息。
- **架构**：**服务端权威**。服务端持有唯一 `GameState`；客户端只收「自己座位的脱敏视图」`getGameView(state, seat)`；动作经 WebSocket 上行，服务端校验后应用并广播。
- **技术选型**：服务端引入 `ws`；身份 = 显示名 + 会话 token（**不做账号**）；房间 = 4~6 位房间码 / URL 参数。
- **任务**：M8-01 房间与 WS 基础设施 → M8-02 服务端权威游戏循环 → M8-03 客户端联机模式 → M8-04 AI 座位由服务端驱动 → M8-05 联机交互窗口与隔离加固 → M8-06 重连/清理/多客户端 E2E。**详见 `docs/开发计划.md` §8.2**。
- **隔离三道保证**：① 每连接绑定唯一 `seat`，只下发该座位视图；② 他人手牌/摸牌牌面/被挑战者手牌一律不出现在下发数据（复用 `sanitizeEventsForSeat`）；③ 不提供「旁观全量」接口。
- **开工前需用户定稿的 4 个决策点**：单机是否保留浏览器端引擎（双路径 vs 统一走服务端）／联机 AI 由谁驱动（服务端 vs 房主客户端）／玩家中途离场处理／断线重连范围。
