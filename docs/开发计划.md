# UNO 本地网页游戏开发计划（v1.2 → v1.3）

> 当前版本 **v1.2**（2026-10-20），M0~M9 已完成；**M10 桌面安装版为规划中**（见 §10），尚未开工。本文是**当前有效的需求、规则规格、架构说明与下一阶段计划**；里程碑历史与逐条任务已压缩，全文见 git 历史。
> 日常启动、玩法与 FAQ 见根目录 [`README.md`](../README.md)；状态台账见 [`开发进度.md`](./开发进度.md)；接续开发先读 [`交接文档.md`](./交接文档.md)。

## 1. 目标与范围

### 1.1 目标

- 本地浏览器运行、可离线游玩的 UNO：1 名真人 + 2~9 名 AI（总人数 2~10）。
- 采用**宽松叠牌**（+2 / +4 任意互叠）与「主动摸牌摸到可出为止」两项本作规则取舍，其余遵循原版 108 张牌规则。
- AI 四档难度（休闲 / 简单 / 真实 / 骨灰级），支持本地启发式与智谱混合决策；在线失败自动降级，不中断对局。
- 局域网联机：服务端权威、房间码进房、按座位隔离信息、断线重连、再来一局。
- 桌面安装版（M10，规划中）：Electron + NSIS，安装后双击进入，不依赖外部浏览器；同一局域网内凭房间码加入；支持玩家自填智谱 Key。

### 1.2 设计原则

- 规则引擎纯函数、可复现 seed、UI 只消费公开视图。
- 前端零构建（原生 HTML/CSS/JS），无框架、无数据库、无账号。
- 联机由服务端裁决；任何客户端拿不到他人手牌与隐藏信息。
- 每完成一个可验证模块即停，等用户测试确认后再继续。

### 1.3 非目标

- 公网服务、账号系统、排行榜、付费/广告、分数与算分。
- 表情自定义上传、表情持久化、文字聊天。
- 联机接入智谱在线决策（当前固定本地启发式）。
- 对局快照恢复（P2）、移动端真机适配（仅基础响应式）。
- M6-03 AI 台词人设库、M6-04 战绩统计页（按用户要求不做）。

## 2. 规则规格

### 2.1 牌组与随机

- 108 张：每色 0 一张、1~9 各两张、Skip/Reverse/DrawTwo 各两张；Wild 4 张、Wild+4 4 张。
- 洗牌用 Fisher–Yates + 可注入种子的 `mulberry32`；相同 seed + 动作序列产生完全相同对局。
- 不做发牌平衡、保底或防连发干预。

### 2.2 对局设置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 玩家数 | 4（2~10） | 单机 1 真人 + AI；联机真人 + AI 补位 |
| 先手 | 随机庄家左手边 | 开局座位随机，不能假设房主先手 |
| 起手翻牌 | 动作牌立即生效 | 可切「忽略动作牌」；起手 +4 放回重洗重翻 |
| 叠牌 | 宽松（loose） | +2 / +4 任意互叠，不看颜色 |
| 2 人特殊规则 | 开 | Reverse=Skip、动作牌后连动 |
| 牌堆耗尽 | 洗回弃牌堆 | 可切「手牌最少者胜」 |
| +4 挑战 | 开 | 挑战判定是否含 Wild 由引擎配置，设置页未暴露 |
| UNO 罚牌 | 2 张 | — |
| 自动喊 UNO | 关 | 设置项 |

### 2.3 回合与合法性

- 单局制，先出完手牌者胜；手牌清空立即结束。
- 正常回合可出合法牌或发起一次摸牌。
- 合法性：数字牌按颜色或数字；动作牌按颜色或图案；Wild 永远可出；Wild+4 永远可点出（允许诈唬，是否违规留给挑战判定）。
- **主动摸牌**：点一次摸牌后逐张摸，直到出现当前可打出的牌才停；之后只能打出刚摸到的这张或结束回合。
  - 一次摸牌聚合为一个 `DRAW` 事件，带实际张数 `count`；他人视角不暴露牌面。
  - 摸牌后手牌必然 >1，清除 `saidUno`。
  - 牌堆中途耗尽先洗回弃牌堆继续；无法补牌则按 2.7 结束，不推进回合。

### 2.4 宽松叠牌

- 打出 +2 / +4 后进入 `stack-response`，下家可选：叠任意 +2、叠任意 +4（选色）、或弃权摸累计张数。
- +2 与 +4 可任意互相叠加，响应阶段**不看颜色**。
- 弃权者摸 `total` 张并失去回合；多人局轮到摸牌者的下一位，2 人局回到最后出叠牌者。
- 叠牌链中的 +4 **不开放挑战**。
- 叠牌过程中手牌清空立即获胜；下家仍播放摸牌动画，但不再结算叠牌链。
- 结束后顶牌颜色取链中最后一张：+2 用其颜色，+4 用最后出牌者所选颜色。

### 2.5 +4 挑战

- 普通回合打出 +4 后，下一位可「摸 4 张」或「挑战」；只有该玩家有挑战权。
- 挑战成功（出牌者手上有当前颜色牌）：出牌者摸 4 张，挑战者不摸并继续回合。
- 挑战失败：挑战者摸 6 张并失去回合。
- 人类挑战 AI 时展示该 AI 手牌 2~3 秒；AI 挑战人类只提示，不向其他玩家泄露。

### 2.6 UNO

- 出牌后剩 1 张进入 `uno-window`（4 秒 + 按钮倒计时）；单击「UNO!」立即喊出，无二次确认。
- 未喊被其他玩家抓到 → 摸 2 张；最后一张出完直接获胜，无需喊。
- 窗口动作按座位过滤：窗口主人只见 CALL_UNO，其他座位只见 CATCH_UNO。
- AI 喊/抓概率随难度：喊 80/95/100/100%，抓 10/40/80/100%。

### 2.7 2 人、牌堆耗尽与结算

- 2 人规则开启时：Reverse 等同 Skip；出 Skip/Reverse 后出牌者再行动；出 +2/+4 后对方摸牌，回合回到出牌者。
- 牌堆耗尽默认洗回弃牌堆；`end-by-fewest` 时手牌最少者胜，并列平局；弃牌堆也不足时同样按最少手牌判定。
- 结算页只展示胜者、剩余手牌、对局时长/回合数与操作统计图表；**不计算、不展示任何分数**。
- 本地战绩仅记录 `uno:stats` 的 games/wins。

### 2.8 关键决策表

| 决策点 | 当前行为 | 可配置 |
| --- | --- | --- |
| 叠牌模式 | 宽松，+2/+4 任意互叠、不看颜色 | 引擎配置位，界面固定宽松 |
| 叠牌链中的 +4 | 不可挑战 | 否 |
| +4 挑战判定 | 不含 Wild（经典） | 引擎配置，设置页未暴露 |
| 挑战成功/失败惩罚 | 出牌者摸 4 / 挑战者摸 6 | 否 |
| 主动摸牌 | 摸到可出为止，只能打刚摸的牌 | 规则固定 |
| 最后一张 +2/+4 | 立即获胜，下家仍摸牌 | 否 |
| UNO 罚牌 | 2 张 | 数值可配 |
| 抓 UNO 多人竞争 | 按座位顺序先到先得，只罚一次 | 否 |
| 结算 | 图表统计，无分数 | 否 |

## 3. 技术架构

### 3.1 技术栈

| 层 | 实现 |
| --- | --- |
| 运行时 | Node.js ≥ 22、npm ≥ 11（开发机 26.7） |
| 引擎 / 服务端 | TypeScript strict；纯函数 reducer |
| 前端 | 原生 HTML + CSS + ES Modules，零构建 |
| 服务端 | Express 5 + ws；静态托管、智谱代理、联机房间 |
| 测试 | Vitest + fast-check；浏览器 E2E 用无头 Chrome/Edge + CDP |
| 质量 | ESLint + Prettier + `tsc --noEmit`；GitHub Actions |

### 3.2 目录

```
apps/web/                前端：index.html、js/{engine,ui,net,animation,audio,state}、styles、cards
apps/server/             本地服务：静态托管、/api、WebSocket 房间
apps/desktop/            桌面壳（M10 规划）：Electron 主进程、preload、UDP 发现、Key 安全存储
packages/game-core/      规则引擎 + public-view + 结算（无 UI/网络依赖）
packages/ai/             本地启发式 AI、四档难度、自对弈
scripts/                 构建、自对弈、验收（verify-ui / verify-online）、卡面处理
docs/                    计划、进度、交接、UI 契约、E2E 指南
research/                CC0 原始卡面与来源说明
```

### 3.3 引擎契约

```ts
createGame(config): GameState
getLegalActions(state, seat): LegalAction[]
applyAction(state, action): { state, events }
getGameView(state, seat, options?): GameView
getHumanLegalActions(state, seat): UiAction[]
getResult(state): GameResult
```

- 纯函数、`structuredClone` 不可变更新；`state.events` 只含本次动作，`state.history` 全量。
- `drawPile` / `discardPile` 数组末尾为堆顶。
- 相位：`await-play` / `choose-color` / `stack-response` / `challenge-decide` / `uno-window` / `round-end`。
- 视图隔离：`drawnThisTurn` 只发给摸牌者；他人 DRAW 事件 `cards=[]`；联机服务端逐座位调用 `getPublicView`。
- 结算无 score 字段；统计字段见 `packages/game-core/src/result.ts`。

### 3.4 前端

- 单页三屏：`lobby` / `game` / `result`，用 `data-screen` 切换；`#dialog-root` 承载弹窗。
- UI 是视图的幂等渲染层：`window.UnoApp` 五个 API（`render` / `playEvents` / `setActionHandler` / `setMockMode` / `getMode`）；DOM 锚点冻结，只增不改。
- 动作 → 引擎 → 新视图 + 事件队列 → 动画串行播放 → 解锁输入；动画期间禁用操作。
- 联机：`js/net/onlineMode.js` 处理 WebSocket、视图队列、断线重连；`js/state/viewer.js` 维护视角座位；`js/ui/emotes.js` 处理表情。
- 设置与战绩存 `localStorage`（`uno:settings` / `uno:stats`）。

### 3.5 服务端与联机

| 能力 | 说明 |
| --- | --- |
| 静态托管 | `apps/web`；`/` 返回首页 |
| `/api/health` | 状态、版本、uptime、实时 `lanUrls` |
| `/api/config` | `aiEnabled` / 模型 / host，不返回 Key |
| `/api/ai/decide` | 智谱代理；超时/限流/非法输出降级本地 |
| `/ws` | 房间码加入、座位分配、动作上行、按座位脱敏广播 |
| 权威循环 | 每房间唯一 `GameState`；人类动作校验，AI/掉线座位服务端代打 |
| 重连 | token 恢复原座位并补发当前视图；房间超时清理 |
| 再来一局 | 房主按原阵容重开（含 AI 补位） |
| 表情 | 12 个纯 emoji；座位校验 + 白名单；每座位 5 条后冷却 2 秒 |

### 3.6 持久化与安全

- 智谱 Key 只存在根 `.env`，仅服务端读取；日志不打印 Key。
- 无数据库；单机状态在内存 + localStorage，联机房间在服务进程内存。
- 联机视图由服务端过滤，前端不接触他人手牌与挑战隐藏信息。
- 启动脚本不自动提权（避免杀软误报）；防火墙规则 `UNO-Local-3000` 需管理员放行一次。

## 4. AI 设计

### 4.1 分层

1. 候选生成：枚举合法动作（Wild/Wild+4 展开四色；含摸牌、叠牌、挑战、UNO）。
2. 本地评分：手牌收益、颜色控制、万能牌价值、对手威胁、叠牌期望、终局、被挑战风险、记牌。
3. LLM 决策（可选）：从候选选一个，返回 `action_id`、理由、台词；不直接生成动作。
4. 校验与兜底：候选校验失败/超时/非 2xx → 本地最高分；UI 标记「本地」或「降级」。

### 4.2 难度

| 维度 | 休闲 | 简单 | 真实 | 骨灰级 |
| --- | --- | --- | --- | --- |
| 失误率 | 20% | 10% | 3% | 0% |
| 记牌 | 无 | 颜色计数 | 全部已出牌 | 全部 + 概率推断 |
| 叠牌 | 有就叠 | 基础 | 主动施压/弃权 | 期望与反叠计算 |
| +4 诈唬 | 从不 | 偶尔 | 视局势 | 高收益时 |
| 挑战 | 10% 乱挑战 | 40% 简单规则 | 概率决策 | 最优阈值 |
| LLM 参与 | 约 30% 回合 | 约 60% | 全部 | 全部 + 关键复盘 |

- 难度只影响策略与表现，不影响规则合法性（+4 诈唬是规则允许行为）。
- 本地 AI 是完整实现，不是占位；`npm run selfplay` 校验难度胜率单调。

### 4.3 LLM 与降级

- 请求串行，回合制天然低并发；动画期间可预取下一位决策。
- 超时默认 6s（2~8s 可配）；失败重试 1 次，仍失败立即本地兜底。
- 输出只接受 JSON，`action_id` 必须命中候选；解析/校验失败重试一次。
- 状态栏显示智谱 / 本地 / 降级；断网或未配 Key 自动走本地。

## 5. UI 与交互

- 顶部：当前颜色、方向、回合、AI 模式、设置、退出。
- 牌桌：2~5 人上方弧形；6~10 人左右两列 + 顶部；每个对手显示头像、名字、牌数、UNO 状态、最近出牌、思考中。
- 手牌：可出高亮上浮，不可出压暗，悬停放大；不显示「你的手牌 / N 张」标题。
- 操作栏只保留功能按钮：摸牌、结束回合、叠牌弃权、UNO!、抓他!、挑战、选色兜底；出牌一律点击手牌。
- 联机牌桌按视角座位渲染，不显示自己；摸牌/出牌动画飞向对应座位。
- 表情：大厅与对局入口，12 个 emoji，气泡显示在发送者座位框下方 2.2 秒。
- 响应式 760 / 1024 断点；支持 `prefers-reduced-motion`、关闭动效、音量与动画速度。

## 8. 运行与配置

```bash
npm install
npm run dev        # 开发模式（自动重建浏览器引擎）
npm start          # 启动本地服务
npm run build:web-engine
```

- 默认地址 `http://localhost:3000`；局域网地址以 `/api/health` 的 `lanUrls` 为准。
- 智谱配置写在根 `.env`（参考 `.env.example`），Key 只在服务端使用。
- Windows 双击 `启动服务.bat`：自动启动并在就绪后打开浏览器；本机无需管理员，局域网首次需右键以管理员身份运行放行防火墙。
- 沙箱/受限环境跑测试时把 `TEMP` / `TMP` 指到 `logs/tmp`。

## 9. 已知限制与后续

- 单机刷新中断对局（无快照恢复）；联机房间在服务进程内存，重启即失效。
- 联机 AI 固定本地启发式；智谱在线决策未接入联机。
- 移动端仅基础响应式，未做真机验收。
- 表情仅纯 emoji，无自定义、历史与文字聊天。
- 结算无分数；`wild4Legality` 仅引擎配置与单测覆盖，未上设置页。
- 未附开源许可证；第三方素材来源见 `research/README.md`。
- 可选后续：联机智谱决策、对局快照、移动端适配、音效素材替换、自动更新与代码签名。
- M10 桌面安装版为当前规划，详见 §10。

## 10. M10 桌面版计划（v1.3，规划中）

> 状态：**规划完成，尚未开工**。按开发约定，收到「开始 M10-01」后才写实现代码。
> 目标产物：`UNO-Setup-1.3.0.exe`（Windows 10/11 x64）。

### 10.1 目标

- 安装后双击桌面图标即可进入游戏，**不依赖外部浏览器**、不要求目标电脑安装 Node.js。
- 一份安装包可分享给他人电脑；单机模式完整可用（四档本地 AI、动效、音效、设置、战绩）。
- 同一局域网内：主机开房，其他玩家**只输入 6 位房间码**即可加入。
- 支持玩家自行填写智谱 API Key；不填 Key 时自动使用本地 AI。
- 网页版继续可用：`npm run dev` / `npm start` 行为不变。

### 10.2 非目标

- 公网联机、公网房间目录、账号系统、排行榜。
- 联机 AI 接入智谱（联机仍固定本地启发式）。
- macOS / Linux 安装包。

### 10.3 技术选型

| 项 | 方案 | 说明 |
| --- | --- | --- |
| 桌面壳 | **Electron** | 内嵌 Chromium + Node，现有 Express/ws 服务与前端原样复用 |
| 安装包 | **NSIS** | 单个安装 exe，生成桌面快捷方式；安装路径稳定，利于防火墙规则 |
| 联机发现 | **UDP 局域网广播/监听** | 主机广播房间码与端口，客户端输入房间码后自动匹配主机地址 |
| 智谱 Key | 玩家自填 + Electron `safeStorage` | Windows 下走 DPAPI；不返回明文、不写日志 |
| 版本 | **v1.3.0** | 桌面版作为 v1.2 之后的功能增量 |
| 平台 | Windows x64 | 首要验证 Windows 10/11 |

### 10.4 总体架构

```
UNO.exe（Electron）
├─ 主进程
│  ├─ 内嵌现有 HTTP + WebSocket 服务
│  │   ├─ 本机页面：http://127.0.0.1:<随机端口>
│  │   └─ 局域网联机：监听 0.0.0.0:<随机端口>
│  ├─ UDP 发现服务（广播房间、监听其他主机）
│  ├─ 智谱 Key 安全存储（safeStorage / DPAPI）
│  ├─ 单实例锁、窗口生命周期、退出清理
│  └─ 服务启动失败 / 端口异常 / 崩溃提示
├─ preload（窄接口）
│  └─ 暴露：发现结果、本机邀请信息、Key 设置与状态
└─ 渲染进程
   └─ 现有 apps/web（大厅、牌桌、结算、联机 UI）
```

新增目录：

```
apps/desktop/
├─ src/main.ts          # Electron 主进程
├─ src/preload.ts       # IPC 窄接口
```

### 10.5 房间码加入流程

1. 主机创建房间，服务端生成 6 位房间码。
2. 主进程每 2 秒通过 UDP 广播：发现协议版本、应用版本、开放房间码列表、HTTP/WS 端口。
3. 客户端输入房间码后：
   - 先查本机房间（同一台电脑开房的场景）；
   - 再查 UDP 发现缓存，匹配房间码，得到主机 IP + 端口；
   - 连接 `ws://<主机IP>:<端口>/ws`，发送现有 `join-room` 消息。
4. 未发现房间时提示：确认主机已开房、双方在同一网络、防火墙已放行；并提供「手动输入主机 IP:端口」兜底。
5. 多个主机使用同一房间码时，列出主机名/IP 让玩家选择。
6. 发现协议携带应用版本；主版本不一致时提示双方使用同一安装包。

### 10.8 智谱 Key 设计

- 存储：`safeStorage.encryptString()` 加密后写入 `userData/zhipu-secret.bin`；Windows 下由 DPAPI 保护。
- 读取：`ZhipuClient` 通过 `apiKeyProvider()` 动态取 Key，保存/清除后立即生效。
- 优先级：玩家保存的 Key > 开发环境 `.env`；安装包不包含 `.env`。
- 前端只获取状态：`{ configured, model, source }`，永不回传明文 Key。
- 设置页提供「保存」「清除」「测试连接」；网页版继续提示通过 `.env` 配置。
- 安全边界：DPAPI 防其他系统用户读取，同账户下的恶意程序仍可能解密；文档中明确说明。

### 10.10 风险与对策

| 风险 | 对策 |
