## 1. 项目概述

### 1.1 一句话目标

做一个**在本地浏览器运行、可离线自娱自乐的 UNO 卡牌游戏**：1 名真人玩家对战 2~9 名 AI（总人数 2~10 可选），采用**宽松叠加加牌**规则，其余规则与 108 张标准牌组全部依照原版；AI 使用**规则引擎 + 智谱免费大模型（GLM-4.7-Flash）的混合决策**，并具备休闲 / 简单 / 真实 / 骨灰级四档难度与多种"套路"。

### 1.2 形态与体验

- **形态**：本地网页游戏（原生 HTML/CSS/JS 前端 + 一个极轻量 Node 本地服务，无框架、无构建步骤）。
- **启动方式**：`npm install` → `npm run dev`（或打包后 `npm start`）→ 浏览器打开 `http://localhost:3000` 即玩。
- **离线能力**：游戏本体与本地 AI 完全离线可玩；只有"智谱大模型增强"部分需要联网，断网 / API 报错时自动降级为本地策略 AI，不中断对局。
- **语言**：全中文 UI 与 AI 台词。
- **胜负**：单局定胜负（先出完手牌者胜），完全随机洗牌，不做任何发牌平衡。

### 1.3 设计原则（贯穿开发）

1. **规则优先**：先把规则引擎做对并测透，再谈 UI 和 AI；引擎是纯 TypeScript、无 UI/网络依赖、可确定性复现。
2. **AI 不作弊**：AI 只能看到"公开信息 + 自己的手牌"，通过 `getPublicView()` 强制隔离，不允许偷看其他玩家手牌。
3. **永不卡死**：任何 AI 决策都必须在有限时间内返回合法动作；LLM 失败 → 本地启发式兜底 → 规则系统兜底（有合法牌可出则出，否则抽牌）。
4. **垂直切片**：先用"1 真人 + 3 简单 AI + 无 API"跑通完整一局，再接智谱、加难度、做打磨。
5. **可配置而非硬编码**：所有规则歧义点（初始翻牌、牌堆耗尽、2 人规则、+4 挑战等）都有默认值 + 配置开关（见 4.12）。

### 1.4 非目标（本期不做）

- **公网**在线联机 / 账号系统 / 排行榜 / 匹配大厅（v1.0 范围不做）。
  > 注：**局域网多人联机 + 用户隔离**已在 v1.0 发布后纳入 **M8**（见 §8.2）；但仍**不做账号体系、不做公网服务、不做排行榜**——保持「无账号、本地自用」定位。
- 商业化、应用商店上架、正式发行（UNO® 为 Mattel 商标，本作仅个人离线自用）。
- 手机端深度适配（先桌面浏览器 1280×800 起，移动端横屏作为 P2 可选）。
- 官方 500 分多局制、7-0 换牌、强制出牌等变体规则（用户已明确不要）。
- 本地部署大模型（Ollama 等）；本期只接智谱 API + 本地启发式 AI。

| # | 决策点 | 用户选择 | 对开发的影响 |
|---|--------|----------|--------------|
| 1 | 运行形态 | **本地网页游戏**（原生 HTML/CSS/JS + Node 本地服务） | npm workspaces：`apps/web`（静态页，零构建）+ `apps/server` + `packages/game-core`；UI 按 `docs/UI开发提示词.md` 实现 |
| 2 | 人类玩家 | 1 人打 AI（座位 0 固定人类） | 对局始终 `1 human + N AI`；热座多人列为 P2 可选 |
| 3 | AI 决策方式 | **混合模式**，并要求"更多 AI 思考和套路" + 四档难度（休闲/简单/真实/骨灰级） | 规则引擎产候选 → 启发式评分 → 智谱模型取舍 + 台词；难度矩阵驱动策略深度（见第 6 章） |

| 7 | 智谱 Key | **已有 Key** | Key 只放服务端 `.env`；开发含真实联调 + 降级测试 |
| 8 | 其他规则/卡牌 | **全部依照原版** | 108 张标准牌组、UNO 喊与抓、+4 挑战、2 人特殊规则等 |

| 决策点 | 默认值 | 说明 |
|--------|--------|------|

## 3. 调研结果

### 3.1 原版 UNO 规则要点（已核实）

**牌组构成（108 张）**——依据 Mattel 官方 UNO 移动游戏官网的牌组说明：

- 76 张数字牌：4 种颜色（红/黄/蓝/绿），每种颜色 19 张 = 数字 0 一张 + 数字 1~9 各两张。
- 24 张动作牌：每种颜色各 2 张 Skip（跳过）、2 张 Reverse（反转）、2 张 Draw Two（+2），共 8 张/色 × 3 种 = 24。
- 8 张万能牌：4 张 Wild（变色）、4 张 Wild Draw Four（+4 变色）。
- 合计：76 + 24 + 8 = **108 张**。

**核心规则**：

- 2~10 人，每人起手 7 张，其余作为抽牌堆，翻顶牌作弃牌堆。
- 回合内打出一张与弃牌堆顶牌"颜色 / 数字 / 图案"匹配的牌；Wild 与 Wild+4 随时可出（Wild+4 有合法性限制）。
- 无牌可出（或不愿出）时抽 1 张，抽到的牌若能出可立即出，否则回合结束。
  > **本作规则变更（2026-10-17 用户要求）**：主动摸牌改为"持续摸牌，直到摸到当前可以打出的牌为止"（一次动作可能摸多张）；牌堆耗尽按 4.9 处理。详见 4.4。
- Skip：下家跳过；Reverse：反转方向（2 人时等同 Skip）；Draw Two：下家摸 2 并跳过；Wild：指定颜色；Wild Draw Four：指定颜色 + 下家摸 4。
- 手牌只剩 1 张时必须喊 "UNO"，被其他玩家在"下家开始行动前"抓到则罚摸 2 张。
- Wild Draw Four 只能在自己没有"当前颜色"的牌时合法打出；下家可选择摸 4 或**挑战**：挑战成功后出牌者摸 4、挑战者不摸；挑战失败则挑战者摸 6（4+2）。
- 原版计分：数字牌面值、动作牌 20 分、万能牌 50 分，先到 500 分获胜（**本作改为单局定胜负，不采用**）。
- 抽牌堆用尽时，把弃牌堆（保留最上面一张）洗回作为新抽牌堆继续。
- 2 人特殊规则（实体规则书）：Reverse 等同 Skip；打出 Skip/Reverse 后可立即再出一张；打出 Draw Two / Wild Draw Four 后，对方摸牌，回合回到出牌者。

**版本差异与处理**：调查中发现不同年份/地区官方说明书在细节上有差异，典型两处：

1. 起手翻牌为动作牌时：旧版说明书是"动作生效由首位玩家承受"；2023 年新版说明书写"忽略动作牌，继续翻下一张"。
2. +4 挑战判定中"手牌里的 Wild 是否算作可替代牌"：新版说明书写 Wild 也算匹配，旧版只算颜色匹配。

处理方式：按 2.2 的默认值实现，并把差异点做成配置开关 + 单测覆盖，避免实现期反复返工。

## 4. 规则规格书（可执行）

> 本章是引擎实现的唯一依据。所有"决策点"都已给出默认值；标 ⚙️ 的项通过 `GameConfig` 可配置。

### 4.1 牌与牌堆

```ts
type Color = 'red' | 'yellow' | 'green' | 'blue';
type CardKind = 'number' | 'skip' | 'reverse' | 'draw2' | 'wild' | 'wild4';

interface Card {
  id: string;          // 例如 "R7#1"（颜色+牌面+序号），全局唯一
  kind: CardKind;
  color: Color | null; // wild/wild4 为 null
  value: 0 | 1 | ... | 9 | null;
  faceCode: string;    // 卡面资源码："R7" / "BA2" / "WC" / "W4"
}
```

**生成规则**（固定顺序生成 → 洗牌）：

- 对每种颜色：数字 0 ×1、数字 1~9 ×2、Skip ×2、Reverse ×2、DrawTwo ×2。
- Wild ×4、Wild Draw Four ×4。
- 总数必须断言为 108；每个 `faceCode` 的出现次数见附录 A。

**洗牌与随机性**：

- Fisher–Yates 洗牌，随机源为可注入种子的 `mulberry32`（默认用 `crypto.randomUUID` / 时间作为种子）。
- 不做任何"平衡发牌""保底出牌""防 +4 连发"等干预（用户明确要求完全随机）。
- 相同 seed 必须产生完全相同的对局，用于测试复现与录像回放。

### 4.2 对局设置

```ts
interface GameConfig {
  playerCount: number;          // 2~10
  humanSeat: 0;                 // 本期固定座位 0
  aiSeats: Array<{
    seat: number;
    difficulty: 'casual' | 'easy' | 'realistic' | 'hardcore';
    persona: PersonaId;
    provider: 'zhipu' | 'local' | 'auto';
  }>;
  startingPlayer: 'random' | 'human';
  startCardRule: 'classic' | 'ignore-action';   // 初始动作牌处理 ⚙️
  stacking: 'loose' | 'classic' | 'none';       // 本作固定 'loose'，保留配置位
  twoPlayerRules: boolean;                      // 默认 true
  deckExhaustion: 'reshuffle' | 'end-by-fewest';// 默认 'reshuffle' ⚙️
  challengeWild4: boolean;                      // 默认 true
  unoPenalty: 2;
  autoCallUno: boolean;                         // 默认 false
  seed?: string;
}
```

**开局流程**：

1. 按 playerCount 创建玩家（座位 0 = 人类，其余 AI），随机庄家或让人类先手（默认随机庄家，庄家左手边先手）。
2. 洗牌 → 每人发 7 张。
3. 翻开抽牌堆顶牌作为弃牌堆第一张，按 2.2 处理起手牌：
   - 数字牌 / Wild：确定当前颜色，游戏开始；若为 Wild，由首位玩家选择颜色。
   - Wild Draw Four：放回抽牌堆、重新洗牌、重新翻（循环直到不是 +4）。
   - Skip：首位玩家被跳过，轮到其下一位。
   - Reverse：方向反转，从原首位玩家的上一位开始（等价于原版"庄家右手边"先手）。
   - Draw Two：首位玩家摸 2 张并跳过，轮到其下一位。
   - ⚙️ `ignore-action` 模式：动作牌一律忽略，继续翻下一张，直到数字/Wild。

### 4.3 回合流程（状态机）

```
LOBBY
  └─ DEALING ──────────────► ROUND_START
                                │
                         ┌──────▼───────┐
                         │  TURN_START  │◄────────────────────────────┐
                         └──────┬───────┘                             │
                                │                                     │
                ┌───────────────┼──────────────────┐                  │
                ▼               ▼                  ▼                  │
        (有 stack 待响应)  (正常回合)         (上一动作已结算)          │
                │               │                  │                  │
                ▼               ▼                  │                  │
      STACK_RESPONSE      AWAIT_PLAY ◄── CHOOSE_COLOR                  │
                │               │                  │                  │
                │               ▼                  │                  │
                │          APPLY_EFFECT ───────────┘                  │
                │               │                                     │
                │               ▼                                     │
                │        UNO_WINDOW（如手牌=1）                         │
                │               │                                     │
                └───────────────┴──────────► TURN_END ────────────────┘
                                                       │
                                            (有人手牌=0) ▼
                                                   ROUND_END
```

**单回合的完整时序**：

1. `TURN_START`：判断当前玩家是否有待处理的 stack（4.5）或挑战窗口（4.6）；有则进入对应子状态，人类玩家等待操作，AI 走自动决策。
2. 正常回合中，当前玩家可以：
   - 出一张合法手牌（Wild/Wild4 需先选色；+4 出牌后进入挑战窗口；+2 出牌后进入 stack 窗口）。
   - 发起摸牌：**持续摸牌直到摸到当前可打出的牌为止**（一次动作可能摸到多张）；随后可选择立即打出这张刚摸到的牌或结束回合。
3. 出牌后结算效果：Skip / Reverse / DrawTwo / Wild / Wild4（DrawTwo、Wild4 进入 stack 子状态等待下家响应）。
4. 若出牌后手牌恰好剩 1 张 → 进入 `UNO_WINDOW`，等待喊 UNO / 被其他玩家抓（见 4.7）。
5. `TURN_END`：按当前方向计算下一位玩家（跳过被 Skip/摸牌跳过的人），回到 `TURN_START`。
6. 任何时刻有玩家手牌清空 → 立即 `ROUND_END`，该玩家获胜。

### 4.4 合法性判定（正常回合）

当前顶牌为 `top`，当前颜色为 `currentColor`（Wild/Wild4 结算后固定为所选颜色），玩家手牌为 `hand`：

| 牌型 | 是否可出 |
|------|----------|
| 数字牌 | `card.color === currentColor` 或 `card.value === top.value`（top 为数字牌时） |
| Skip / Reverse / DrawTwo | `card.color === currentColor` 或 `card.kind === top.kind`（图案相同） |
| Wild | 永远可出（任意时刻） |
| Wild Draw Four | 永远可点出（原版允许诈唬）；是否"合法"留到挑战时判定（4.6） |
| 摸牌 | 永远可选（即使有牌可出），每回合最多发起 1 次；**一次摸牌持续摸到出现可打出的牌为止** |

- **摸牌规则（2026-10-17 用户要求变更）**：一次「摸牌」动作从抽牌堆逐张摸牌，摸到第一张"当前可打出的牌"立即停止，此时 `drawnThisTurn` = 该牌，只允许打出刚摸到的这张牌或结束回合；过程中摸到的其余牌留在手里。
  - 牌堆中途耗尽：默认把弃牌堆洗回后继续摸；`end-by-fewest` 或弃牌堆也不足时按 4.9 直接结束本局（不推进回合）。
  - 摸牌后手牌必然 >1，因此旧的 `saidUno` 状态会被清除（下次再出到 1 张需重新喊 UNO）。
  - 一次 `DRAW` 动作产生 **1 个聚合 `DRAW` 事件**（`count`=实际摸牌张数，`cards`=全部摸到的牌；他人视角不暴露牌面）。
- **摸牌后**：只允许出刚摸到的那张（若可出），或直接结束回合；不允许改出其他手牌。
- **+4 的"匹配"争议**：默认按"当前颜色"判定合法性（手上是否有当前颜色牌），Wild 不算匹配；⚙️ 可切换为"新版：Wild 也算匹配"。
- **+2 叠 +2 的色彩**：stack 响应阶段无视颜色（见 4.5），因此合法性判定在 stack 阶段单独实现。

### 4.5 叠加加牌（宽松叠法，本作核心差异）

**定义**：任意玩家在正常回合打出 `draw2` 或 `wild4` 后，产生一个"叠牌链"（stack）：

```ts
interface StackState {
  total: number;        // 累计要摸的张数
  chain: Card[];        // 已打出的叠牌链（按顺序）
  lastPlayer: number;   // 最后一张叠牌的出牌者
  topColor: Color;      // 最后一张叠牌结算后的颜色
  awaitingSeat: number; // 当前必须做出响应的玩家
}
```

**响应规则**（`STACK_RESPONSE` 状态，轮到 `awaitingSeat` 的玩家）：

| 选项 | 条件 | 结果 |
|------|------|------|
| 出 +2 | 手里有任意 +2（**不看颜色**） | `total += 2`；链追加；颜色变为该 +2 的颜色；轮转下一位 |
| 出 +4 | 手里有任意 +4（**不看颜色**） | `total += 4`；链追加；出 +4 者选色，颜色变为所选颜色；轮转下一位 |
| 弃权 / 没有叠牌 | — | 该玩家摸 `total` 张，失去回合；stack 清空；轮到该玩家之后的下一位 |

- 叠牌是**可选操作**：即使手里有 +2/+4 也可以选择摸牌放弃。
- 宽松叠法下 **+2 与 +4 可任意互相叠加**：+2 可以压在 +4 上，+4 也可以压在 +2 上。
- 叠牌链中的 +4 **不开放挑战**（因为下一家的选择是"叠牌或摸牌"，不是原版的"摸 4 或挑战"）——这是为兼容叠加而明确的规则决定；⚙️ 未来可提供"叠牌链中仍可挑战"的开关，但本期不做。
- 叠牌过程中若出牌者手牌剩 1 张 → 正常进入 `UNO_WINDOW`。
- 若有人在叠牌过程中手牌清空（最后一张是 +2/+4）→ 立即结束本局，获胜；**下家仍播放摸牌动画**（仪式感），但不再结算叠牌链，也不影响胜负。
- 2 人模式下：对方摸完 `total` 张后，回合回到最后出叠牌的人（与官方 2 人连动规则一致）。
- 多人模式下：摸牌者失去本回合，轮到摸牌者的下一位开始正常回合。
- 颜色规则：叠牌结束后，桌面顶牌是链中最后一张牌——若最后一张是 +4，颜色为最后出 +4 者所选颜色；若最后一张是 +2，颜色为该 +2 的颜色。

**累计示例**：A 出 +2 → B 叠 +4（选蓝）→ C 叠 +2（红）→ D 弃权，则 D 摸 2+4+2 = **8 张**，之后轮到 E 正常出牌，当前颜色为红。

**实现要点（伪代码）**：

```ts
function resolveStackDraw(state, seat) {           // 玩家弃权
  drawCards(state, seat, state.stack.total);
  const next = nextSeat(state, state.stack.awaitingSeat); // 摸牌者的下一位
  clearStack(state);
  return next;
}

function playStackCard(state, seat, card, colorChoice?) {
  state.stack.total += card.kind === 'draw2' ? 2 : 4;
  state.stack.chain.push(card);
  state.stack.lastPlayer = seat;
  state.stack.topColor = card.kind === 'draw2' ? card.color : colorChoice;
  state.currentColor = state.stack.topColor;
  moveCard(state, seat, card);
  state.stack.awaitingSeat = nextSeat(state, seat);
}
```

### 4.6 +4 挑战（原版规则）

**触发**：在**普通回合**中，玩家打出 Wild Draw Four（不经过叠牌链），且下一位玩家选择不叠牌时，该下一位玩家二选一：

- **摸 4 张**：接受原版效果，失去回合。
- **挑战**：查看出牌者手牌，判定出牌者出 +4 之前手上是否有"当前颜色"的牌（默认不含 Wild；⚙️ 可配置为包含 Wild）。

**判定与惩罚**：

| 情况 | 结果 |
|------|------|
| 出牌者**有**当前颜色的牌（违规出牌） | 出牌者摸 4 张；挑战者**不摸牌**，继续其回合（按 +4 所选颜色出牌或抽牌） |
| 出牌者**没有**当前颜色的牌（合法出牌） | 挑战失败：挑战者摸 **6** 张（4+2）并失去回合；轮到挑战者的下一位 |

- 只有"即将被迫摸 4 张的下一位玩家"有挑战权，其他玩家不能挑战。
- 挑战时展示手牌：人类挑战 AI 时，向人类展示该 AI 的完整手牌 2~3 秒（还原实体规则中"挑战者查看手牌"）；AI 挑战人类时，只向该 AI 展示人类手牌并计入其"已看到的牌"记忆（人类玩家看到提示"AI 查看你的手牌"），**不向其他玩家/其他 AI 泄露**。
- 叠牌链中的 +4 不开放挑战（见 4.5）。
- 人类与 AI 都可以选择诈唬：明知手上有当前颜色牌仍出 +4，赌对方不挑战；被挑战则受罚。

### 4.7 UNO 喊与抓

- **触发**：任意玩家出牌后手牌恰好剩 1 张 → 进入 `UNO_WINDOW`（该玩家需要在"下一位玩家开始行动前"喊 UNO）。
- **人类**：
  - 出牌后出现醒目的「UNO!」按钮（默认不自动喊）；点击即喊成功。
  - 若人类忘记喊，AI 可能在本窗口内抓人（概率随难度：休闲 10% / 简单 40% / 真实 80% / 骨灰级 100%）。被抓 → 人类摸 2 张。
  - 人类也可以抓 AI：当某个 AI 剩 1 张且还没喊时，UI 显示「抓他！」按钮（窗口期约 2~3 秒或直到下一位玩家行动）；点击成功 → 该 AI 摸 2 张。
- **AI**：按难度概率自动喊 UNO（休闲 80% / 简单 95% / 真实 100% / 骨灰级 100%），未喊时玩家可抓；AI 之间也会互相抓（概率同抓人类）。
- **窗口关闭**：下一位玩家"开始行动"（出牌 / 抽牌 / 叠牌响应）即关闭，之后不能再抓。
- **罚牌**：被抓者摸 2 张。
- **边界**：最后一张牌出完直接获胜，无需喊 UNO；出第 2 张牌（剩 1 张）时必须喊。

### 4.8 2 人特殊规则 ⚙️

当玩家总数为 2 且 `twoPlayerRules = true`：

- Reverse 等同 Skip（下家被跳过）。
- 出 Skip / Reverse 后，出牌者立即再行动一次（连动）。
- 出 Draw Two / Wild Draw Four 后，对方摸牌，回合回到出牌者（连动）。
- 与叠加结合：叠牌结算后（对方摸了累计牌），回合回到最后出叠牌者，行为一致。
- 关闭该选项后，2 人使用与多人完全相同的回合规则。

### 4.9 牌堆耗尽

- 默认（原版）：抽牌堆为空时，把弃牌堆除最上面一张外的所有牌洗回抽牌堆，继续游戏。
- ⚙️ 可选 `end-by-fewest`：抽牌堆耗尽即结束本局，手牌最少者胜；若并列最少则平局。
- 若弃牌堆也无法提供牌（极端情况，如全员手牌巨大且弃牌堆不足）→ 按手牌最少者判定，并在事件日志标注。

### 4.10 胜负与结算（单局制）

- 第一个手牌清空的玩家即获胜，立即结束本局。
- 结算页展示（2026-10-18 用户要求：**取消分数计算**，保留最终结算并改为数据图表总结操作）：胜者、各玩家剩余手牌、对局时长/总回合数、**操作统计**（每人出牌 / 摸牌 / 叠牌 / 喊 UNO / 被抓 UNO / 挑战次数；全局动作构成）与**数据图表**（每位玩家操作堆叠条、全体动作构成环形图、剩余手牌颜色构成堆叠条）。不再计算或展示任何分数。
- 战绩（localStorage）：总场次、胜场、连胜、最高单局分数，按 AI 难度分档统计。

### 4.11 边界与异常清单

- 抽牌堆剩 0/1 张时触发的摸牌效果（先补牌堆再结算）。
- 多人同时具备抓 UNO 资格时：按座位顺序先到先得，只处罚一次。
- LLM 超时/报错：不阻塞规则，直接本地兜底。
- 人类刷新页面（P2 可选）：对局状态快照存 localStorage 可恢复。
- 窗口切换导致动画暂停：使用事件队列 + 恢复时重放（不强制）。
- 人类误点：出牌前无二次确认（保持流畅），设置里可开启"打出前确认"。

### 5.3 游戏引擎（`packages/game-core`）

**设计原则**：

- 纯函数 reducer：`applyAction(state, action) => { state, events }`，不直接改传入对象（可用 Immer 或手写不可变更新）。
- 无 React/DOM/fetch/localStorage 依赖，Node 与浏览器通用，Vitest 可直接跑。
- 所有随机行为走可注入 RNG；相同 seed + 相同动作序列 ⟹ 完全相同状态。
- UI 与 AI 都只能通过 `getPublicView(state, seat)` 读状态，从 API 层面杜绝"看别人手牌"。

**核心 API**：

```ts
export function createGame(config: GameConfig): GameState;
export function getLegalActions(state: GameState, seat: number): LegalAction[];
export function applyAction(state: GameState, action: Action):
  { state: GameState; events: GameEvent[] };
export function getPublicView(state: GameState, seat: number): PublicView;
export function isTerminal(state: GameState): boolean;
export function getResult(state: GameState): GameResult;
```

**核心类型（初稿）**：

```ts
type Phase =
  | 'lobby' | 'dealing' | 'turn-start' | 'await-play'
  | 'choose-color' | 'stack-response' | 'challenge-decide'
  | 'uno-window' | 'turn-end' | 'round-end';

interface PlayerState {
  seat: number; name: string;
  hand: Card[];
  saidUno: boolean;
  isHuman: boolean;
  aiConfig?: AiConfig;
}

interface GameState {
  config: GameConfig;
  phase: Phase;
  players: PlayerState[];
  drawPile: Card[];
  discardPile: Card[];        // 末尾为顶牌
  currentColor: Color;
  currentSeat: number;
  direction: 1 | -1;
  stack: StackState | null;
  pendingChallenge: { challenger: number; target: number } | null;
  unoWindow: { seat: number; canCatch: number[] } | null;
  drawnThisTurn: Card | null;
  winnerSeat: number | null;
  turnCount: number;
  events: GameEvent[];        // 事件日志（UI 动画/AI 上下文/录像）
  rng: RngState;
}

type Action =
  | { type: 'PLAY_CARD'; seat: number; cardId: string; colorChoice?: Color }
  | { type: 'DRAW' }
  | { type: 'PLAY_DRAWN'; cardId: string; colorChoice?: Color }
  | { type: 'END_TURN' }
  | { type: 'CHOOSE_COLOR'; color: Color }
  | { type: 'STACK_PLAY'; cardId: string; colorChoice?: Color }
  | { type: 'STACK_DECLINE' }
  | { type: 'CHALLENGE_W4' }
  | { type: 'DECLINE_CHALLENGE' }     // 接受摸 4
  | { type: 'CALL_UNO' }
  | { type: 'CATCH_UNO'; targetSeat: number };
```

**事件日志**（`GameEvent`）：`DEAL`、`PLAY`、`DRAW`、`SKIP`、`REVERSE`、`COLOR_SET`、`STACK_PUSH`、`STACK_RESOLVE`、`CHALLENGE_SUCCESS`、`CHALLENGE_FAIL`、`UNO_CALLED`、`UNO_CAUGHT`、`PENALTY`、`PILE_RESHUFFLE`、`PLAYER_OUT`、`ROUND_END` 等。事件同时驱动：UI 动画、AI 上下文摘要、测试断言、对局统计。

**实现顺序建议**：`types → rng/deck → legal → engine(reducer) → effects → stacking → challenge → uno → tests`。每完成一个模块立刻补单测。

### 5.4 前端架构

**页面与屏幕切换**（单页，`data-screen` 切换，不引入 router）：

- **大厅 Lobby**：玩家名、总人数（2~10）、AI 难度（统一 + 逐个高级设置）、AI 模式（智谱/本地/自动）、开始游戏、设置/战绩入口。
- **牌桌 Game**：核心对局页（布局见 7.2）。
- **结算 Result**：胜者、剩余手牌、操作统计图表、再来一局 / 回大厅（2026-10-18 起取消分数）。
- **弹窗层** `#dialog-root`：选色、+4 挑战、UNO、设置、确认。
- **开发工具条**（仅 mock 模式）：切换 10 种 mock 局面，便于 UI 独立开发。

**渲染与状态**：

- UI 是"引擎视图模型的纯渲染层"：`window.UnoApp.render(view)` 幂等全量渲染（按区域：玩家区 / 中央牌堆 / 手牌 / 操作栏 / 弹窗），不从 DOM 反推状态。
- 人类操作 → `onAction(action)`（引擎注册的回调）→ `applyAction` → 新 view + events → `playEvents(events)` 动画 → 解锁输入 → 推进下一位。
- 动画队列与输入锁：动画期间禁用操作并设置 `aria-busy`；AI 的"思考延迟"也算队列时间；AI 决策可提前并行请求，不阻塞动画。
- 本地持久化：`js/state/settings.js` 管理 `uno:settings` / `uno:stats`。
- **UI 与引擎的完整契约见 [`UI开发提示词.md`](./UI开发提示词.md)**（GameView / UiAction / GameEvent / DOM 锚点 / window.UnoApp API）。UI 可先用 mock 数据独立开发，对接时契约不变。

### 5.5 后端（`apps/server`）

**职责**：静态资源托管（生产）、智谱 API 代理、配置读取、健康检查。**不承担游戏逻辑**（引擎在前端运行，单机游戏无防作弊需求）。

**路由**：

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/health` | 服务存活检查 |
| GET | `/api/config` | 返回 `{ aiEnabled, model, baseUrlHost }`，绝不返回 Key |
| POST | `/api/ai/decide` | 混合决策：接收公开状态 + 候选 + 难度/人设，返回选择的 actionId + 理由 + 台词 |
| POST | `/api/ai/banter` | （可选）单独生成台词 |
| POST | `/api/ai/test` | 设置页"测试智谱连接"按钮，发一次最小请求 |

**智谱客户端要点**：

- Base URL / 模型 / Key 全部来自环境变量；请求超时 8s（可配）；失败重试 1 次（指数退避 + 抖动）。
- `response_format: { type: 'json_object' }` 优先；若模型不支持则提示词约束 + 解析修复。
- 日志脱敏：不打印 Key；请求/响应只记录长度、耗时、模型名。
- 错误映射：401 → "Key 无效"；429/1302 → "触发限流，已降级本地 AI"；1305 → "平台过载"；超时 → "本地 AI 接管"。

**运行模式**：无前端构建步骤。开发与生产都是同一个 Node server：静态托管 `apps/web/` + 提供 `/api` 代理，默认地址 `http://localhost:3000`。

### 6.2 候选动作生成（所有难度共用）

| 场景 | 候选 |
|------|------|
| 正常回合 | 每张可出的牌（Wild/Wild4 展开为 4 个颜色选项）；"摸牌"（摸到可出为止，随后"打出刚摸到的牌"/"结束回合"） |
| 叠牌响应 | 每张 +2 / +4（+4 展开 4 种颜色）；"弃权摸牌" |
| 面对 +4 | "接受摸 4"；"挑战" |
| 选颜色 | 红/黄/蓝/绿 4 个候选（在手牌中该色数量、下家可能缺色等特征） |
| UNO 决策 | "喊" / "不喊" |
| 抓 UNO | "抓" / "不抓" |

每个候选包含：`id`、动作类型、`score`（本地启发式 0~1）、`features`（手牌变化、颜色控制、下家威胁、被挑战风险等）、`note`（中文一句话，供 LLM 参考，如"打红7：保留蓝牌，下家红牌概率低"）。

### 6.3 本地启发式评分（核心特征）

```
score(candidate) =
  w1 * 手牌减少/牌型收益          // 数字牌先走、动作牌价值
+ w2 * 颜色控制（保留强色/避开下家颜色）
+ w3 * 万能牌保留价值（越到残局越值钱）
+ w4 * 对手威胁（下家手牌越少越要压）
+ w5 * 叠牌期望（累积张数 vs 被反叠风险）
+ w6 * 终局收益（剩 2 张时的必胜路径）
- w7 * 被挑战/被反制风险
+ w8 * 记牌信息（该颜色剩余数量）
+ 难度噪声（休闲/简单随机扰动）
```

四档难度的区别在于：**特征是否启用、权重、随机噪声、搜索深度、LLM 参与度**（见 6.4）。

> **摸牌规则变更后的 AI 期望（2026-10-17）**：一次摸牌不再固定 1 张，而是摸到出现可打出的牌为止。`drawCost` 特征从常量 1 改为**期望摸牌数**：用公开信息估计"随机一张未知牌可打出"的概率 p（万能牌永远可出 + 当前颜色的剩余牌；保守忽略同数字/同图案跨色匹配），期望 `E ≈ 1/p`（上限 12），特征值按 `E/3` 归一（以期望摸 3 张为 1 个单位，钳制到 0~1）。这样 AI 仍会把"主动摸牌"视为有代价的行为，但代价随局面（未知牌里能打出的比例）自适应。

### 6.4 难度矩阵

| 维度 | 休闲 Casual | 简单 Easy | 真实 Realistic | 骨灰级 Hardcore |
|------|-------------|-----------|----------------|------------------|
| 定位 | 陪你玩、会犯错、话多 | 规则正确、水平一般 | 像普通老玩家 | 近乎最优 + 心理战 |
| 决策来源 | 启发式 + LLM 轻量 | 启发式 + LLM 常规 | 启发式 + LLM 深度 | 启发式搜索 + LLM 深度 |
| 失误率 | 20%（随机选低分牌） | 10% | 3% | 0% |
| 记牌 | 完全不记 | 只记已出颜色数量 | 全部已出牌 | 全部已出牌 + 概率推断 |
| 颜色选择 | 手牌最多色 | 手牌最多色 + 简单权重 | 考虑下家可能缺色 | 综合剩余牌统计与下家手牌数 |
| 针对策略 | 无 | 偶尔压手牌最少者 | 会针对领先者 / 手牌少者 | 精确打击 + 保送自己 |
| 叠牌博弈 | 有 +2/+4 就叠 | 基础判断 | 会主动开叠逼下家、会弃权 | 精确计算累计期望与反叠链 |
| +4 诈唬 | 从不 | 偶尔（10%） | 会（视局势 30%） | 精确诈唬（高收益时） |
| 挑战判断 | 10% 概率乱挑战 | 40% 按简单规则 | 按信息概率决策 | 概率阈值最优 + 行为建模 |
| UNO 喊 / 抓 | 80% / 10% | 95% / 40% | 100% / 80% | 100% / 100% |
| LLM 参与 | 只问关键决策（约 30% 回合） | 约 60% 回合 | 每个决策都问 | 每个决策 + 关键节点二次复盘 |
| 思考延迟 | 0.8~1.5s | 1~2s | 1.5~3s | 2~4s（可设置"快速模式"缩短） |
| 台词风格 | 憨憨话多、爱自夸 | 简短 | 正常交流、偶尔嘲讽 | 话少但毒舌、心理战 |
| API 消耗 | 低 | 中 | 高 | 最高（仍免费） |

> 难度只影响"策略与表现"，**不影响规则合法性**：所有 AI 都只能出合法牌（+4 诈唬除外，那是原版允许的规则行为）。

### 6.5 AI 套路库（实现清单）

1. **颜色陷阱**：记下已出牌后，选出下家最可能没有的颜色；手牌少时优先清空某一种颜色。
2. **万能牌管理**：万能牌留到残局 / 关键解除卡手；避免在能正常出牌时浪费。
3. **叠牌博弈**：主动 +2 逼下家叠或摸；手握 +4 时计算"叠到多少对方会弃权"；被叠时评估是否反叠。
4. **+4 精准炸**：对下家手牌少的玩家使用；在自身有同色牌时诈唬（原版规则允许），赌对方不敢挑战。
5. **挑战决策**：根据"该玩家历史出过的颜色 / 最近是否留牌 / 手牌数 / 之前是否诈唬过"估算违规概率，超过阈值就挑战。
6. **针对领先者**：多人局中优先压制手牌最少 / 连胜的玩家（人类玩家会是重点照顾对象，难度越高越明显）。
7. **终局必胜**：剩 2 张时选择能保证下一回合出完的牌型；避免只留一张 +4 被反制。
8. **UNO 博弈**：AI 自己准时喊；记住谁"忘喊"过，提高抓人率；高难度会故意在语音上施压（台词）。
9. **记牌与概率**：统计各颜色剩余数量，估算抽到某色/某数字的概率；高难度会推算"对手卡手"概率。
10. **行为建模**：记录玩家出牌偏好（爱留什么色、爱不爱叠、爱不爱挑战），骨灰级会利用这些信息。
11. **节奏控制**：快赢时加快出牌（表演性），被压制时"思考"更久（拟人）。
12. **心理战台词**：根据局势生成短台词（"我就知道你没红牌"），纯娱乐，不影响规则。

> 以上策略全部基于**公开信息**（已出牌、手牌数、公开动作）。挑战时看到的手牌属于原版规则允许的公开事件，AI 会记住并在本局后续合法使用（与真人玩家一致）。

### 6.6 LLM 决策 Prompt 设计

**系统提示词模板**（按难度/人设渲染）：

```text
你是本地 UNO 单机版中的 AI 对手「{name}」，性格：{persona_desc}，难度：{difficulty}。
规则摘要：
- 108 张标准 UNO，2~10 人；叠加采用宽松叠法：+2 与 +4 可任意互相叠加，接不上的人摸累计张数并失去回合。
- 单局定胜负，先出完手牌者胜；其余按官方规则（含 UNO 喊牌、+4 挑战）。
- 你只能使用给你的公开信息和自己的手牌，禁止假设能看到其他玩家手牌。
你的风格：{difficulty_style}
任务：从候选动作中选择一个最优动作，并给出：
1) action_id（必须是候选列表中的 id）
2) reason（中文一句话，≤40 字，仅用于思考展示说明）
3) line（对玩家说的一句中文台词，≤20 字，可为空字符串）
输出要求：只输出 JSON，不要输出 Markdown 或额外文字。
```

**输出 JSON Schema**（zod 校验）：

```ts
const DecisionSchema = z.object({
  action_id: z.string().min(1),
  reason: z.string().max(80).default(''),
  line: z.string().max(40).default(''),
});
```

**校验与兜底**：

1. `JSON.parse` 失败 → 发一次修复提示重试（把原文 + 错误信息回给模型）。
2. zod 校验失败 → 同上。
3. `action_id` 不在候选里 → 再重试一次；仍错则取启发式最高分候选。
4. 请求超时（默认 3.5s，可配 2~8s）/ 非 2xx / 限流 → 立即本地兜底，UI 侧不报错，只把 AI 标记为"本地决策"。

**参数建议**：

| 难度 | temperature | max_tokens | 调用频率 |
|------|-------------|------------|----------|
| 休闲 | 0.9 | 200 | 关键决策（约 30%） |
| 简单 | 0.7 | 250 | 约 60% |
| 真实 | 0.5 | 350 | 全部 |
| 骨灰级 | 0.3 | 450 | 全部 + 关键节点二次复盘 |

> 二次复盘仅用于"骨灰级"的关键节点（如 +4 是否出、被叠是否反叠、终局选择），两次调用之间不共享隐藏信息；结果仍只从候选里选。

### 6.7 人设与台词

- 人设池（每局随机分配，增加变化）：稳健老手、激进赌徒、佛系玩家、记仇型、话痨、沉默高手、嘴硬型。
- 人设只影响：台词风格、部分策略权重（如激进取更多叠牌）、思考延迟微调；不影响合法性。
- 台词来源：① 本地台词库（按事件触发，离线可用）；② LLM 生成的 `line`（在线时）。做长度限制与简单过滤，避免不适内容。
- UI 用气泡展示台词，设置中可关闭"AI 闲聊"。

### 6.8 性能、成本与降级

- **请求串行**：回合制、同一时刻只有一个 AI 决策请求，完全适配免费模型的低并发额度。
- **预取**：在当前回合动画播放时，提前请求下一位 AI 的决策（若已知下一位且状态可确定），减少等待感。
- **延迟目标**：本地 AI < 5ms；LLM 决策 P50 ≤ 2.5s，P95 ≤ 5s；超时立即兜底。
- **成本**：GLM-4.7-Flash 免费；即使切换付费模型，一局 10~40 次调用、每次约 1~2K tokens，单局成本可忽略。
- **降级链**：智谱 → 重试 1 次 → 本地启发式（相同难度参数）→ 规则兜底（能出就出，否则抽牌）。UI 状态栏显示当前 AI 模式（智谱 / 本地 / 降级中）。
- **断网**：设置 `AI 模式 = 自动` 时自动切换本地，无需玩家干预。

### 6.9 本地 AI 也必须有完整表现

- 本地启发式 AI 不是"占位符"：四档难度都要有对应策略（记牌、叠牌、挑战、抓 UNO 等），保证断网/未配置 Key 时游戏依然完整可玩、有挑战性。
- 用 `scripts/selfplay.ts` 跑 AI vs AI 基准：不同难度对战胜率应呈单调关系（休闲 < 简单 < 真实 < 骨灰级），若不符合则调权重。

## 7. UI / UX 与视觉方案

### 7.1 设计目标

- **一眼看懂**：当前颜色、方向、谁在行动、可出哪些牌、下一位是谁，必须清晰。
- **操作顺滑**：单击出牌（或拖拽可选），Wild 选色弹窗 ≤ 2 次点击完成。
- **节奏感**：AI 有"思考中"提示与拟人延迟，出牌有动画和音效。
- **还原感**：卡面接近原版，牌桌绿色绒布，经典红白配色 UI。

### 7.2 牌桌布局

```
┌────────────────────────────────────────────────────────────────────┐
│ 顶部栏：局数 / 当前颜色 / 方向 / AI 模式 / 设置 / 退出              │
├────────────────────────────────────────────────────────────────────┤
│                  [AI1]      [AI2]      [AI3]                       │
│                  7张        5张        9张                          │
│                                                                    │
│        [AI8]    ┌──────────────┐    [AI4]                          │
│        6张      │              │    4张                            │
│                 │  弃牌堆 抽牌堆 │                                   │
│                 │  [顶牌][牌背]  │   ← 当前颜色光环                 │
│        [AI7]    └──────────────┘    [AI5]                          │
│        8张                          7张                            │
│                  [AI6] 6张                                         │
│                                                                    │
│  事件流/台词区（滚动，最近 3 条）                                    │
│                                                                    │
│  ┌────────────────────────── 你的手牌 ──────────────────────────┐  │
│  │  [R7] [GS] [B0] [W4] [Y+2] ...（重叠排列，可出牌高亮）        │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  [抽牌] [UNO!] [抓他!] [挑战] [取消]        ← 上下文按钮，按需显示  │
└────────────────────────────────────────────────────────────────────┘
```

- 2~5 人：AI 排在上方弧形；6~10 人：左右两侧各一列，顶部一排。
- 每个 AI 显示：头像（emoji / 首字母）、名字、手牌数（牌背小图标 + 数字）、UNO 状态、"思考中…"提示、最近一次出的牌。
- 人类手牌区：可出牌亮起 + 上浮；不可出牌压暗；悬停放大；当前必须响应时（如叠牌）按钮区显示对应操作。
- **2026-10-17 UI 精简（用户要求，M3-3）**：手牌区不再显示「你的手牌 / N 张」标题；操作栏只保留功能按钮（摸牌 / 结束回合 / 叠牌弃权 / UNO! / 抓他! / +4 挑战 / 选色兜底），出牌一律通过鼠标点击手牌完成；正常回合提示条为空（仅叠牌/挑战/选色/UNO 等特殊阶段显示提示）。契约 DOM 锚点与 `window.UnoApp` API 不变。

### 7.3 关键交互流程

1. **出牌**：点击可出的牌 →（Wild/Wild4 弹出四色选择）→ 牌飞向弃牌堆 → 结算效果 → 下一位。
2. **叠牌响应**：轮到你响应时，可出的 +2/+4 高亮；点击手牌即叠；也可点操作栏「摸 X 张」放弃。
3. **+4 挑战**：上家出 +4 后，弹出二选一：「摸 4 张」/「挑战！查看手牌」。挑战后展示结果与惩罚动画。
4. **UNO**：出牌后剩 1 张 → 操作栏出现醒目的大号「UNO!」按钮（脉冲高亮）；**单击一次立即喊出**（无二次确认）；若没点，AI 可能抓你；AI 忘喊时出现「抓他！」按钮。
5. **结算**：遮罩 + 结果卡片 + 再来一局。

### 7.4 可访问性与适配

- 键盘：`1~9` 选牌、`Enter` 出牌、`D` 抽牌、`U` 喊 UNO、`Esc` 关闭弹窗。
- 色盲友好：设置中可开启"卡面角标图案"（数字/符号形状叠加）。
- 响应式：桌面优先 1280×800；1024×768 可用；移动端横屏作为 P2。
- 减少动态效果：跟随系统 `prefers-reduced-motion`。

### 9.2 AI 测试

- **合法性**：`scripts/simulate.ts` 跑 4 档难度 × 2~10 人 × 各 1000 局：非法动作数必须为 0。
- **信息隔离**：单测断言 `getPublicView(state, seat)` 不包含其他玩家手牌；LLM 请求体快照中无隐藏信息。
- **难度单调性**：两两对战各 200 局（座位交替），强档胜率应满足 休闲 < 简单 < 真实 < 骨灰级。
  - 2026-10-17 摸牌规则变更后（见 4.4），单局回合数约翻倍、方差增大，200 局样本胜率的 95% 置信区间约 ±7%；因此 `npm run selfplay` 允许 **2% 统计容差**（强档胜率 ≥48% 视为"不弱于"）与 **4 人混战相邻名次差 ≤0.15** 的容差，仍能拦截真实反转（强档 <48%）。
  - 参考区间同步调整：平均回合数 **60~160**（旧规则为 20~60）；4 人混战平均名次仍应随难度单调变好。
  - BUG-01 之后 AI 的 `drawCost` 特征改为"期望摸牌数/3"（见 6.3），自对弈复核：非法动作 0、错误 0、难度阶梯与混战排名均通过。
- **LLM 健壮性**：mock 服务端返回非法 JSON / 空 / 超时 / 限流 / 非法 action_id 各 100 次，游戏必须继续且最终正常结束。
- **挑战/抓 UNO 行为**：按难度概率统计（允许置信区间），确认难度参数生效。
- **LLM 冒烟测试**（`scripts/smoke-ai.ts`，需要 Key）：一次真实调用，验证模型、JSON 输出、耗时；不放入默认 `npm test`（避免依赖网络/额度）。

## 12. 运行与配置指南

### 12.1 环境要求

- Windows 10/11（当前开发机）或其他系统。
- Node.js ≥ 22（当前 26.7.0）、npm ≥ 11。
- 现代浏览器（Chrome / Edge 最新版）。
- 联网（仅 AI 增强需要；首次 `npm install` 需要）。

### 12.2 配置智谱 Key

1. 打开 <https://bigmodel.cn/usercenter/proj-mgmt/apikeys> 创建/复制 API Key（用户已有 Key，可直接用）。
2. 在项目根目录创建 `.env`（从 `.env.example` 复制）：

```dotenv
# 智谱开放平台
ZHIPU_API_KEY=你的Key
ZHIPU_BASE_URL=https://open.bigmodel.cn/api/paas/v4
ZHIPU_MODEL=glm-4.7-flash
# 备用模型（逗号分隔，失败自动切换）
ZHIPU_FALLBACK_MODELS=glm-4.5-flash,glm-4-flash
# AI 决策超时（毫秒）
AI_DECISION_TIMEOUT_MS=3500
# 本地服务端口
PORT=3000
```

3. 启动后在设置页点"测试智谱连接"，看到模型回复即成功。
4. 不配置 Key 也能玩：AI 自动使用本地启发式。

### 12.3 常用命令（目标形态）

```bash
npm install            # 安装依赖
npm run dev            # 开发：启动本地 server（静态托管 + AI 代理），打开 http://localhost:3000
npm start              # 生产：同 dev（无构建步骤）
npm run test           # 引擎/AI 单测
npm run test:watch     # 监听模式
npm run lint           # ESLint + tsc --noEmit
npm run fetch:cards    # 重新下载/处理卡面
npm run selfplay       # AI 自对弈基准
npm run smoke:ai       # 智谱连通性冒烟（需 Key）
```

### 12.4 常见问题

| 现象 | 原因/处理 |
|------|-----------|
| 页面提示"AI 已切换本地" | Key 未配置/无效/超时/限流；检查 `.env` 与设置页测试 |
| 401 Unauthorized | Key 错误或未生效；重新复制 Key |
| 1302 / 429 | 触发限流；降低 AI 频率或稍后重试（游戏自动兜底） |
| 端口占用 | 改 `PORT` 或关闭占用进程 |
| 卡面 404 | 未跑 `npm run fetch:cards`；或文件名/路径不对 |
| 浏览器无法联网 | 本地 AI 模式；不影响游戏 |

```ts
      model,
      messages,
      temperature: 0.5,
      max_tokens: 400,
      response_format: { type: 'json_object' }, // 模型不支持时自动降级为纯提示词
      stream: false,
    }),
    signal: AbortSignal.timeout(Number(process.env.AI_DECISION_TIMEOUT_MS ?? 3500)),
  });
  if (!res.ok) throw new Error(`Zhipu HTTP ${res.status}`);
  const data = await res.json();
  return data.choices?.[0]?.message?.content ?? '';
}
```

> OpenAI 兼容接口也支持用 `openai` npm 包：`new OpenAI({ apiKey, baseURL: 'https://open.bigmodel.cn/api/paas/v4' })`，两者等价，按实现方便选。
