# 产品与架构基线（v2.0.0 阶段）

> 基线版本 **v1.3.0**；v2.0.0 为 UI/交互重构，不改规则、AI、联机协议与桌面壳。
> v1 里程碑与桌面版细节见 [`v1-开发归档.md`](./v1-开发归档.md)；执行方案见 [`v2.0.0-UI重构开发方案.md`](./v2.0.0-UI重构开发方案.md)（M1~M8），总体目标见 [`v2.0.0-UI开发计划.md`](./v2.0.0-UI开发计划.md)（V2-00~V2-07）。

## 1. 目标与范围

- 本地浏览器可玩 UNO：1 真人 + 2~9 AI（总人数 2~10），单机离线可用。
- **宽松叠牌**（+2/+4 任意互叠）+ **主动摸牌摸到可出为止**；其余遵循原版 108 张规则。
- AI 四档难度，本地启发式 + 可选智谱混合决策，失败自动降级。
- 局域网联机：服务端权威、房间码、按座位隔离、断线重连、再来一局。
- 桌面版：Electron + NSIS，内嵌服务，UDP 附近房间、手动 `IP:端口`、智谱 Key 自填。
- **v2.0.0 只做 UI**：token、牌桌回合层级、手牌/操作区、大厅、结算、动效与无障碍。

**非目标**：跨网公网联机、账号/排行榜、分数、表情自定义/持久化、联机智谱决策、对局快照、移动端原生适配、台词人设库、战绩统计页。

## 2. 规则规格

### 2.1 牌组与随机

- 108 张：每色 0 一张、1~9 各两张、Skip/Reverse/DrawTwo 各两张；Wild 4、Wild+4 4。
- Fisher–Yates + 可注入种子的 `mulberry32`；相同 seed + 动作序列产生相同对局。

### 2.2 对局设置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 玩家数 | 4（2~10） | 单机 1 真人 + AI；联机真人 + AI 补位 |
| 先手 | 随机 | 开局座位随机，不能假设房主先手 |
| 起手翻牌 | 动作牌生效 | 可切忽略；起手 +4 放回重洗重翻 |
| 叠牌 | 宽松 | +2/+4 任意互叠，不看颜色 |
| 2 人特殊规则 | 开 | Reverse=Skip、动作牌后连动 |
| 牌堆耗尽 | 洗回弃牌堆 | 可切「手牌最少者胜」 |
| +4 挑战 | 开 | 是否含 Wild 由引擎配置，设置页未暴露 |
| UNO 罚牌 | 2 张 | — |
| 自动喊 UNO | 关 | 设置项 |

### 2.3 回合与合法性

- 单局制，先出完手牌者胜；正常回合可出合法牌或摸一次牌。
- 数字牌按颜色/数字；动作牌按颜色/图案；Wild 永远可出；Wild+4 永远可点（允许诈唬，由挑战判定）。
- **主动摸牌**：逐张摸到出现可出牌为止；之后只能打刚摸的牌或结束回合。
- 一次摸牌聚合为一个 `DRAW` 事件；他人视角不暴露牌面；摸牌后清除 `saidUno`。
- 牌堆中途耗尽先洗回弃牌堆；无法补牌则按最少手牌结束，不推进回合。

### 2.4 宽松叠牌

- 打出 +2/+4 后进入 `stack-response`，下家可叠任意 +2、叠任意 +4（选色），或弃权摸累计张数；响应阶段不看颜色。
- 弃权者摸 `total` 张并失去回合；多人局轮到摸牌者下一位，2 人局回到最后出叠牌者。
- 叠牌链中的 +4 不开放挑战；叠牌中手牌清空立即获胜；结束后顶牌颜色取链中最后一张。

### 2.5 +4 挑战

- 普通回合打出 +4 后，只有下一位可选择「摸 4 张」或「挑战」。
- 挑战成功：出牌者摸 4 张，挑战者不摸并继续回合；失败：挑战者摸 6 张并失去回合。
- 人类挑战 AI 时展示该 AI 手牌 2~3 秒；AI 挑战人类只提示，不泄露。

### 2.6 UNO

- 出牌后剩 1 张进入 `uno-window`（当前固定 4 秒；v2 M5 起按难度 10/8/6/4 秒，见重构方案）；单击「UNO!」立即喊出，无二次确认。
- 未喊被其他玩家抓到 → 摸 2 张；最后一张出完直接获胜。
- 窗口动作按座位过滤：窗口主人只见 `CALL_UNO`，其他座位只见 `CATCH_UNO`。
- 喊/抓概率随难度：喊 80/95/100/100%，抓 10/40/80/100%。

### 2.7 2 人、牌堆耗尽与结算

- 2 人规则开启：Reverse 等同 Skip；出 Skip/Reverse 后再行动；出 +2/+4 后回合回到出牌者。
- 牌堆耗尽默认洗回；`end-by-fewest` 时手牌最少者胜，并列平局；弃牌堆不足时同样判定。
- 结算只展示胜者、剩余手牌、时长/回合数与操作统计；**不计算、不展示分数**；战绩仅 `games/wins`。

### 2.8 关键取舍

- 叠牌链中的 +4 不可挑战；+4 挑战判定不含 Wild；挑战成/败惩罚 4/6 张。
- 最后一张 +2/+4 立即获胜，下家仍摸牌；多人抓 UNO 按座位顺序先到先得，只罚一次。

## 3. 技术架构

### 3.1 技术栈

| 层 | 实现 |
| --- | --- |
| 运行时 | Node.js ≥ 22、npm ≥ 11 |
| 引擎 / 服务端 | TypeScript strict；纯函数 reducer；Express 5 + ws |
| 前端 | 原生 HTML + CSS + ES Modules，零构建 |
| 测试 / 质量 | Vitest + fast-check；无头 Chrome/Edge + CDP；ESLint + Prettier + `tsc --noEmit` |

```
packages/game-core/src/   types/config/rng/deck/setup/legal/engine/result/public-view
packages/ai/src/          candidates/scoring/decide/selfplay/difficulty/memory
apps/web/js/              engine、net/onlineMode、ui、state/viewer、animation、audio
apps/server/src/          index/routes/zhipu/ai-key/static/net（protocol/rooms/wsServer）
apps/desktop/src/         main/preload/ipc/paths/environment/secretStore/discovery
scripts/                  verify-ui / verify-online / verify-desktop / selfplay / build
```

### 3.2 引擎契约

```ts
createGame(config): GameState
getLegalActions(state, seat): LegalAction[]
applyAction(state, action): { state, events }
getGameView(state, seat, options?): GameView
getHumanLegalActions(state, seat): UiAction[]
getResult(state): GameResult
```

- 纯函数、`structuredClone` 不可变更新；`state.events` 只含本次动作，`history` 全量；牌堆末尾为堆顶。
- 相位：`await-play` / `choose-color` / `stack-response` / `challenge-decide` / `uno-window` / `round-end`。
- 视图隔离：`drawnThisTurn` 只发摸牌者；他人 `DRAW` 事件 `cards=[]`；联机逐座位调用 `getPublicView`。

### 3.3 前端

- 单页三屏 `lobby` / `game` / `result`，`data-screen` 切换；`#dialog-root` 承载弹窗。
- UI 幂等渲染：`window.UnoApp` 五个 API（`render` / `playEvents` / `setActionHandler` / `setMockMode` / `getMode`）；DOM 锚点只增不改。
- 动作 → 引擎 → 新视图 + 事件队列 → 动画串行播放 → 解锁输入。
- 联机：`onlineMode.js` 处理 WS/视图队列/重连；`viewer.js` 维护视角座位；表情与设置存 `localStorage`。

### 3.4 服务端与联机

| 能力 | 说明 |
| --- | --- |
| 静态托管 / `/api/health` | `apps/web`；状态、版本、uptime、`lanUrls` |
| `/api/config` / `/api/ai/decide` | 不返回 Key；智谱代理，超时/限流/非法输出降级本地 |
| `/ws` | 房间码加入、座位分配、动作上行、按座位脱敏广播 |
| 权威循环 | 每房间唯一 `GameState`；人类动作校验，AI/掉线座位服务端代打 |
| 重连 / 再来一局 | token 恢复原座位并补发视图；房主按原阵容重开 |
| 表情 | 12 个纯 emoji；座位校验 + 白名单；每座位 5 条后冷却 2 秒 |

- 安全：智谱 Key 来源为桌面自填（`safeStorage`/DPAPI，优先）> 根 `.env`；只在服务端使用，日志不打印，IPC 不回传明文。
- 无数据库；联机房间在服务进程内存；启动脚本不自动提权，防火墙规则 `UNO-Local-3000`。

## 4. AI 设计

1. 候选生成：枚举合法动作（Wild/Wild+4 展开四色；含摸牌、叠牌、挑战、UNO）。
2. 本地评分：手牌收益、颜色控制、万能牌价值、对手威胁、叠牌期望、终局、被挑战风险、记牌。
3. LLM 决策（可选）：从候选选一个，返回 `action_id`、理由、台词；不直接生成动作。
4. 校验兜底：候选校验失败/超时/非 2xx → 本地最高分；UI 标记「本地」或「降级」。

| 维度 | 休闲 | 简单 | 真实 | 骨灰级 |
| --- | --- | --- | --- | --- |
| 失误率 | 20% | 10% | 3% | 0% |
| 记牌 | 无 | 颜色计数 | 全部已出牌 | 全部 + 概率推断 |
| 叠牌 | 有就叠 | 基础 | 主动施压/弃权 | 期望与反叠计算 |
| +4 诈唬 / 挑战 | 从不 / 10% | 偶尔 / 40% | 视局势 / 概率 | 高收益 / 最优阈值 |
| LLM 参与 | 约 30% | 约 60% | 全部 | 全部 + 关键复盘 |

- 难度只影响策略，不影响合法性；请求串行，超时默认 6s，失败重试 1 次后本地兜底。
- 只接受 JSON，`action_id` 必须命中候选；状态栏显示智谱/本地/降级。
- `npm run selfplay` 的「真实 vs 骨灰级」单调断言仍未过，属历史遗留。

## 5. UI 与交互

- 顶部：当前颜色、方向、回合、AI 模式、设置、退出。
- 牌桌：2~5 人上方弧形；6~10 人左右两列 + 顶部；对手显示头像、名字、牌数、UNO、最近出牌、思考中、1~5 张卡背。
- 手牌：可出高亮上浮，不可出压暗，悬停放大；不显示「你的手牌 / N 张」标题。
- 操作栏只保留功能按钮：摸牌、结束回合、叠牌弃权、UNO!、抓他!、挑战、选色兜底；出牌一律点击手牌。
- 联机按视角座位渲染；表情气泡在发送者座位框下方 2.2 秒。
- 响应式 760 / 1024 断点；支持 `prefers-reduced-motion`、关闭动效、音量与动画速度。
- **v2.0.0 详细目标、token、层级与验收见 [`v2.0.0-UI重构开发方案.md`](./v2.0.0-UI重构开发方案.md)、[`v2.0.0-M1-视觉契约.md`](./v2.0.0-M1-视觉契约.md) 与 [`v2.0.0-UI开发计划.md`](./v2.0.0-UI开发计划.md)。**

## 7. 运行与配置

```bash
npm install
npm run dev        # 开发模式（自动重建浏览器引擎）
npm start          # 启动本地服务
npm run build:web-engine
```

- 默认地址 `http://localhost:3000`；局域网地址以 `/api/health` 的 `lanUrls` 为准。
- 智谱配置写在根 `.env`（参考 `.env.example`），Key 只在服务端使用。
- Windows 双击 `启动服务.bat` 自动启动并开浏览器；局域网首次可能需管理员放行防火墙。
- 受限环境跑测试时把 `TEMP` / `TMP` 指到 `logs/tmp`。

## 8. 已知限制与后续

- 单机刷新中断对局；联机房间在服务进程内存；联机 AI 固定本地启发式。
- 移动端仅基础响应式，未做真机验收；表情仅纯 emoji。
- 结算无分数；`wild4Legality` 未暴露；未附开源许可证。
- 桌面安装包未签名，真实 GUI/安装/DPAPI 待验收。
- 当前联机只支持本机、局域网房间码与手动 `IP:端口`；跨网公网暂缓。
- 可选后续：联机智谱决策、对局快照、移动端适配、音效素材、自动更新与签名。
