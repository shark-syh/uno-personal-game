# v2.0.0 UI 重构开发方案与阶段约定

> 状态：M1 契约已产出，待用户验收；仅用于评审与分阶段执行。
> 
> 当前基线：v1.3.0；M13「对手手牌可视化」MVP 已完成。
> 
> 参考 Demo：`review-assets/v2-ui-prototype/v2.0.0-demo.html`。Demo 只作为视觉参考，不视为生产代码。
>
> **M1 已产出（2026-10-23）**：12 条批注映射、token、断点、座位角度、DOM 契约、文案表、UNO 10/8/6/4、获胜牌来源、截图场景、断言替换与回滚边界见 [`v2.0.0-M1-视觉契约.md`](./v2.0.0-M1-视觉契约.md)。M1 仍只写文档，生产代码未改；待用户验收后再进入 M2。

## 一、改了什么（文件、可视化）

### 1. 本次方案的硬约束

- 保留现有深绿色主题、UNO 原始牌面和卡片风格；变化集中在空间结构、信息层级、状态表达和动效节奏。
- 品牌只显示 `UNO Local` 与当前版本号，不使用额外产品副标题。
- 大厅开局标题统一为「开启对局」；开发表述统一为「v2.0.0 UI 重构与交互升级」。删除宣传式副文案。
- 牌桌采用自适应圆形主布局。牌桌中心固定突出上一张出的牌、当前颜色和行动状态；角色信息贴合座位，不再使用独立角色卡片框。
- 对手手牌继续使用 M13 的 `handCount` 和卡背视觉，不泄露牌面；M13 已有的 `.opponent-hand`、`.opponent-hand-card`、`data-hand-count`、`data-visible`、`data-layout="fan"` 作为稳定契约。
- 删除音效按钮。音效状态不再占用牌桌顶部的可视控件位置；已有设置和内部音频能力是否保留，按现有设置入口与回归结果处理。
- 玩家手牌改为贴合交互窗口的悬浮牌层，背景与牌桌融合；不再使用独立「你的手牌」容器标题来分割空间。
- UNO 按钮仅在玩家手牌剩 1 张且当前处于可喊 UNO 窗口时出现。按钮外圈显示金色倒计时环，**窗口按难度为休闲 10s / 简单 8s / 真实 6s / 骨灰级 4s**；倒计时结束后按钮消失或进入既有罚牌流程，不能改变规则引擎裁决。
- 结算页使用明确的科技感胜利填充，保证文字不重叠；显示获胜者最后打出的牌，并支持从牌桌位置平滑移动到结算位置。
- 结算头部改为对局总结数据优先：胜者、局数、手数、用时、行动统计等。删除「按事件类型查看本局行动构成」说明文案。

### 2. 预计涉及的生产文件

| 文件 | 计划职责 | 适配边界 |
| --- | --- | --- |
| `apps/web/styles/tokens.css` | 深绿色主题、层级、间距、圆形牌桌尺寸、焦点和状态 token | 只整理 UI token，不改规则含义 |
| `apps/web/styles/layout.css` | 大厅、圆形牌桌、座位锚点、悬浮手牌、结算布局和响应式 | 保持既有 `data-screen` 与主要 DOM 锚点 |
| `apps/web/styles/components.css` | 开局按钮、状态标签、UNO 环、弹窗、操作反馈 | 不引入新的规则动作 |
| `apps/web/styles/cards.css` | 中央上一张牌、玩家手牌、对手卡背和合法性状态 | 复用现有卡牌资源与卡片比例 |
| `apps/web/styles/animations.css` | 牌桌到结算的转场、回合变化、UNO 倒计时、牌数变化 | 支持动画关闭和 `prefers-reduced-motion` |
| `apps/web/js/ui/players.js` | 圆形座位定位、M13 卡背堆、当前回合状态 | 只消费公开视图，不扩展协议 |
| `apps/web/js/ui/table.js` | 中央弃牌、当前颜色、方向和上一手牌状态 | 不重写引擎事件和回合状态机 |
| `apps/web/js/ui/hand.js` | 悬浮手牌、合法性、选择和动作区关联 | 保留点击手牌出牌的现有动作契约 |
| `apps/web/js/ui/hud.js` | `UNO Local`、版本号、当前回合摘要 | 删除 Demo 中的音效按钮，不改变设置存储契约 |
| `apps/web/js/ui/result.js` | 对局总结、胜利牌、转场承接和统计布局 | 只消费 `result` 与事件队列，不重新计算规则 |
| `apps/web/js/animation/*` | 事件到视觉转场的串行播放与可中断处理 | 不让重复 render 重启已完成动画 |
| `scripts/verify-ui.mjs` | 圆形布局、UNO 显示条件、倒计时、结算和溢出断言 | 扩展现有验证，不替换正式入口 |
| `scripts/verify-online.mjs` | 联机视角隔离、对手卡背和座位适配断言 | 不放宽手牌隐私断言 |
| `docs/开发进度.md`、`CHANGELOG.md` | 分阶段状态、版本 tag 和发布记录 | 只有用户同意阶段后才更新完成状态 |

### 3. 明确不改的代码边界

- 不修改 `packages/game-core/src/*`、`packages/ai/src/*` 的规则、AI 候选动作、结算和难度语义。
- 不修改 GameView、`handCount`、座位隔离、WebSocket 协议和服务端公开视图字段。
- 不把 UI 倒计时当成规则计时；UNO 是否成功、是否罚牌仍由现有引擎状态和服务端裁决。
- 不恢复 M11/M12 跨网公网联机，不新增账号、排行榜、数据库、主题市场或前端框架。
- `review-assets/v2-ui-prototype/*` 只用于评审和截图，除非单独授权，不将 Demo 代码复制进生产目录。

### 4. M1—M8 阶段分布

#### M1：视觉契约与文案收敛

- **目标**：把本次 12 条批注固定为可实现的视觉、文案、状态和 DOM 规则，锁定截图基线。
- **文件**：新增 [`v2.0.0-M1-视觉契约.md`](./v2.0.0-M1-视觉契约.md)；更新 `docs/v2.0.0-UI重构开发方案.md`、`docs/开发进度.md`（仅在阶段同意后更新）；读取 `review-assets/v2-ui-prototype/v2.0.0-demo.html`。
- **代码边界**：不改生产 HTML/CSS/JS，不改 Demo。
- **可视化**：确认深绿色桌面、原始卡片、圆形牌桌、悬浮手牌、金色 UNO 环、科技感结算填充为唯一 v2 方向。
- **可能问题**：Demo 与生产 DOM 不完全一致；文案改动可能触发现有 E2E 文本定位。
- **修改规则**：先用稳定的 `id`、`data-*` 和状态字段替代脆弱文本定位；文案只改显示层，不改变动作名称和事件类型。
- **验收**：批注 1—12 均有对应规则；视觉 token、断点、动效关闭策略、截图场景和回滚边界完成评审。
- **产出（2026-10-23）**：契约已写入 [`v2.0.0-M1-视觉契约.md`](./v2.0.0-M1-视觉契约.md)；本节验收项在该文档 §14 逐条勾选，等待用户确认后关闭 M1。

#### M2：大厅与顶部品牌重构

- **目标**：完成大厅大外观重构，压缩宣传信息，建立开局入口的明确层级。
- **文件**：`apps/web/index.html`、`apps/web/styles/layout.css`、`apps/web/styles/components.css`、`apps/web/js/ui/lobby.js`、`apps/web/js/ui/hud.js`、对应 `verify-ui` 断言。
- **代码边界**：保留现有「开启对局」、配置、联机和设置动作；不改配置对象和房间协议。
- **可视化**：顶部只显示 `UNO Local` + 当前版本号；主按钮显示「开启对局」；主内容显示「v2.0.0 UI 重构与交互升级」；次级入口退居辅助层。
- **可能问题**：旧测试依赖旧标题；窄屏配置项可能被键盘或安全区遮挡。
- **修改规则**：显示文案通过单一常量维护；主操作只能有一个视觉主按钮；任何隐藏次级入口必须仍可键盘访问。
- **验收**：1440、1024、760、420 宽度下开局路径可见且可操作；既有单机和联机入口均可进入；无音效按钮残留。

#### M3：圆形牌桌与座位布局重构

- **目标**：将牌桌从多块角色卡片改为以圆形为主的自适应空间，突出中心上一手牌。
- **文件**：`apps/web/js/ui/players.js`、`apps/web/js/ui/table.js`、`apps/web/styles/layout.css`、`apps/web/styles/cards.css`、`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`。
- **代码边界**：不改变座位号、视角换位、`currentSeat`、`handCount`、`lastPlayed` 和联机脱敏逻辑。
- **可视化**：圆形牌桌使用容器尺寸或 `aspect-ratio` 稳定缩放；中心固定显示上一张牌；角色姓名、牌数、UNO 和当前回合状态贴合圆周锚点，不再各自包成独立角色框。
- **可能问题**：10 人局、760/420 宽度和长名字容易拥挤；圆形缩放可能造成牌面与座位标签重叠。
- **修改规则**：先确定桌面直径和最小直径，再按座位数计算锚点；卡牌尺寸跟随牌桌缩放但设上下限；任何装饰元素不得覆盖中心牌和可操作手牌。
- **验收**：2/4/10 人、单机/联机不同视角下座位顺序正确；中心上一手牌始终可见；无角色框叠层、横向溢出或牌面泄露。

#### M4：悬浮手牌与动作区适配

- **目标**：把玩家手牌融入交互窗口，形成沉浸式悬浮牌层，同时保持现有点击出牌逻辑。
- **文件**：`apps/web/js/ui/hand.js`、`apps/web/styles/cards.css`、`apps/web/styles/layout.css`、`apps/web/styles/components.css`、`scripts/verify-ui.mjs`。
- **代码边界**：不新增出牌规则，不把不可出牌变成可点击，不改 `UiAction`；手牌仍由公开视图驱动。
- **可视化**：取消「你的手牌」分隔标题；手牌下沿与操作窗口融合；合法牌、选中牌、不可用牌、刚摸到牌拥有不同但克制的状态；手牌过多只在手牌区域滚动。
- **可能问题**：悬浮层可能遮挡操作按钮；移动端横向滚动可能被误判为页面滚动；重渲染可能导致选择状态丢失。
- **修改规则**：手牌区域建立独立滚动边界；所有触控目标至少 44px；选择状态由稳定的卡牌 id 恢复；动画期间沿用现有输入锁。
- **验收**：桌面端牌面不跳动；420 宽度可横向浏览手牌且页面不横向溢出；键盘可选中、取消和出牌；现有合法性断言全部通过。

#### M5：UNO 条件与金色倒计时环

- **目标**：将 UNO 交互收敛为单张牌窗口，增加难度相关的金色环形反馈。
- **文件**：`apps/web/js/ui/hand.js`、`apps/web/styles/components.css`、`apps/web/styles/animations.css`、`apps/web/js/animation/*`、`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`。
- **代码边界**：不修改引擎 UNO 规则、罚牌数量、联机动作权限；UI 倒计时不能替代服务端计时或裁决。
- **可视化**：仅当玩家手牌为 1 张且处于 `uno-window` 时显示 UNO 按钮；外圈金色进度环顺时针消失；窗口按难度 10/8/6/4 秒；结束后按钮隐藏并显示既有状态反馈。
- **可能问题**：客户端与服务端时间漂移；难度变化是否影响真人窗口存在规则歧义；倒计时动画可能在重复 render 时重启。
- **修改规则**：映射已确认（2026-10-23）：休闲 10s、简单 8s、真实 6s、骨灰级 4s；M1 已锁定联机沿用、AI 参与边界与服务端权威计时（见 [`v2.0.0-M1-视觉契约.md`](./v2.0.0-M1-视觉契约.md) §7）；动画通过状态 diff 启动一次，禁止每次 render 重置。
- **验收**：0 张和大于 1 张时不显示按钮；1 张且窗口开放时显示；环的剩余时间与状态一致；`prefers-reduced-motion` 和关闭动画时保留文字倒计时/静态边框，不持续闪烁。

#### M6：结算转场与对局总结

- **目标**：让最后一张获胜牌成为结算视觉锚点，并以总结数据取代说明性文案。
- **文件**：`apps/web/js/ui/result.js`、`apps/web/js/animation/*`、`apps/web/styles/animations.css`、`apps/web/styles/components.css`、`scripts/verify-ui.mjs`。
- **代码边界**：不重新计算胜者、手数、用时、行动统计；只消费现有 `result` 和事件数据；不泄露他人手牌。
- **可视化**：最后打出的牌从牌桌中心或出牌位置平滑移动至结算页获胜牌位；对局背景与结算背景交替淡化/浮出；胜利文字使用不重叠的彩色科技感填充；结算头部显示胜者、局数、手数、用时和总行动等数据；删除「按事件类型查看本局行动构成」。
- **可能问题**：刷新或联机延迟时找不到上一张牌；转场期间用户重复点击；窄屏标题与统计重叠。
- **修改规则**：缺少飞行源节点时使用静态入场降级；转场期间锁定重复动作；标题、获胜牌和统计分别拥有稳定布局槽位；`prefers-reduced-motion` 下直接淡入结算。
- **验收**：真人获胜、AI 获胜、平局/无获胜牌均有可读结算；牌移动不遮挡标题；总结数据与结果对象一致；移动端无文字重叠。

#### M7：响应式、无障碍与性能收口

- **目标**：把大幅视觉变化收敛为可长期使用的 UI，覆盖移动触控、键盘和低动态模式。
- **文件**：`apps/web/styles/tokens.css`、`apps/web/styles/layout.css`、`apps/web/styles/components.css`、`apps/web/styles/animations.css`、`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`。
- **代码边界**：不以响应式分支复制规则逻辑；不为装饰卡背加入可访问名称；不取消既有视角隔离。
- **可视化**：420/760/1024/1440 四档下圆桌、中央牌、悬浮手牌和操作区保持稳定；安全区、触控反馈、焦点环和 disabled 状态清晰；低动效模式仍保留信息层级。
- **可能问题**：移动端 100vh、刘海安全区、滚动穿透、悬停样式残留、过多卡背节点造成布局抖动。
- **修改规则**：使用 `min-height: 100svh`/安全区变量；触控设备不依赖 hover；手牌区域允许滚动，页面禁止意外横向滚动；所有动效提供静态降级；优先 transform/opacity，避免动画期间反复触发布局。
- **验收**：键盘路径完整、焦点可见、必要状态有 `aria-live` 或文本；卡背 `aria-hidden="true"`；桌面目标接近 60 FPS；低动效和关闭动画均无持续闪烁。

#### M8：协同测试、回归与 v2.0.0 发布

- **目标**：以可复现的协同测试结果确认 UI 改造没有破坏规则、联机和桌面边界。
- **文件**：`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`、必要时 `scripts/verify-desktop` 相关文件、`docs/开发进度.md`、`CHANGELOG.md`、截图和报告目录。
- **代码边界**：只修复由 UI 重构直接引入的回归；发现规则或协议问题时停止 UI 阶段并单独记录，不顺手扩大范围。
- **可视化**：生成大厅、圆桌、UNO 窗口、结算转场、窄屏和联机视角的验收截图；对照 Demo 与生产实现逐项勾选。
- **可能问题**：自动化通过但真实触控/桌面窗口仍有偏差；Electron 沙箱无法启动；旧截图或文案断言失效。
- **修改规则**：自动化、人工浏览器、真实触控/桌面三类结果分开记录；`SKIP` 不等于通过；任何失败必须关联到具体阶段和复现尺寸。
- **验收**：`npm test`、`npm run typecheck`、`npm run lint`、`npm run verify:ui`、`npm run verify:online` 通过；桌面端按可用环境完成启动/窗口/静态资源检查；文档、截图、版本号和变更日志同步。

## 二、还剩什么

### 1. 仍待确认的规则

- **UNO 倒计时映射（已确认）**：休闲 10s、简单 8s、真实 6s、骨灰级 4s。M1 结论：时长用于 UI 环呈现与单机 AI 推进节奏；窗口开/关仍由引擎/服务端状态机裁决，不新增超时罚牌；联机沿用房间难度映射。详见 M1 契约 §7。
- **UNO 窗口结束行为（已确定）**：沿用当前引擎的窗口关闭/罚牌行为；UI 环结束后隐藏入口并提示，不自行提交罚牌动作。
- **音效入口范围（已确定）**：Demo 顶部音效按钮不带入生产；设置页「音效」「音效音量」保留，`uno:settings` 存储契约不变。
- **角色信息最小字段（已确定）**：保留头像、姓名、牌数、UNO、思考、台词、`lastPlayed`、M13 卡背；420 仅隐藏头像与卡背，精确牌数和当前回合必须保留。
- **获胜牌来源（已确定）**：`view.table.discardTop`，仅 `result.reason === 'empty-hand'` 时飞入；平局/牌堆耗尽/源缺失静态降级；不改协议、不读隐藏手牌。
- **科技感胜利填充（已确定）**：只作用于标题文字和获胜牌边缘光，一次 520ms；不引入大面积背景渐变或高频闪烁。
- **结算「局数」（已确定，待用户否决）**：当前一局定胜负，不使用恒为 1 的「局数」；头部显示「人数 / 手数 / 用时 / 行动」。

### 2. 开发中可能出现的问题

- 现有 UI 自动化若依赖旧文案，需要改为稳定 `id`、`data-state` 或可访问名称；不能为了保留旧断言而保留已取消的宣传文案。
- 圆形牌桌在 10 人局和小屏幕上可能出现锚点拥挤；允许按人数降低卡牌和标签尺寸，但不能隐藏精确牌数和当前行动信息。
- 悬浮手牌与操作区共享空间后，可能出现滚动、焦点、点击命中和动画层级问题；每个问题需记录视口、座位数和状态，不用全局 z-index 叠加解决。
- UNO 倒计时如果绑定 render，会在 AI 更新或联机事件到达时重置；必须通过状态 diff 或独立 timer 生命周期处理。
- 胜利牌转场可能因事件队列、刷新或联机延迟缺少源节点；静态降级必须与动态路径等价可读。
- 圆形布局与手牌动画可能增加布局计算；动画优先使用 transform/opacity，完成后清理临时 class 和节点。
- 自动化截图通过不代表真机触控通过；移动端安全区、键盘、滚动和 Electron 窗口必须单独记录。
