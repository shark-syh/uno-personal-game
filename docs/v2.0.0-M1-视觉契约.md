### 4.2 座位锚点

圆心为桌面中心 `(50%, 50%)`；玩家（视角座位）固定在桌面下方手牌区，不计入 `#opponents`。对手数量 `N = players.length - 1`，相对座位 `i = 1..N`（从玩家左侧开始顺时针）。

| 对手数 N | 角度（CSS，0°=右，90°=下） |
| --- | --- |
| 1 | 270 |
| 2 | 210, 330 |
| 3 | 180, 270, 360 |
| 4 | 160, 220, 320, 380 |
| 5 | 150, 210, 270, 330, 390 |
| 6 | 150, 198, 246, 294, 342, 390 |
| 7 | 150, 190, 230, 270, 310, 350, 390 |
| 8 | 150, 184, 219, 254, 286, 321, 356, 390 |
| 9 | 150, 180, 210, 240, 270, 300, 330, 360, 390 |

JS 只负责计算并写入：

```html
<article class="opponent seat" data-seat="2" data-relative-seat="1"
         data-hand-count="3" data-visible="3" data-layout="fan"
         style="--seat-x: 27.8%; --seat-y: 29.1%; --seat-angle: 210deg;">
```

CSS 负责：

```css
.opponent.seat {
  position: absolute;
  left: clamp(calc(var(--v2-seat-w) / 2 + 8px), var(--seat-x),
             calc(100% - var(--v2-seat-w) / 2 - 8px));
  top: clamp(calc(var(--v2-seat-h) / 2 + 6px), var(--seat-y),
            calc(100% - var(--v2-seat-h) / 2 - 6px));
  transform: translate(-50%, -50%);
}
```

规则：

1. `--seat-x = 50% + 46% * cos(angle)`，`--seat-y = 50% + 40% * sin(angle)`；JS 计算，CSS 只消费。
2. `data-seat` 保留真实座位号；`data-relative-seat` 用于布局与测试；不得交换。
3. 座位顺序按视角座位旋转，保证自己永远在下方；联机换座后顺序必须正确。
4. 座位内信息顺序：头像 → 姓名 → 牌数/UNO → M13 卡背 → `lastPlayed` → 当前回合描边。
5. 姓名最多一行，`text-overflow: ellipsis`；`aria-label` 保留完整「姓名，N 张牌」。
6. W6 隐藏头像与 `.opponent-hand`，但保留姓名、精确牌数、UNO、`lastPlayed`、当前回合。
7. 座位 chip 不得覆盖 `#table-center`；以桌面中心为圆心，中心牌安全区半径 ≥ `max(中心牌宽, 高) / 2 + 16px`。

### 5.4 DOM 规则

1. **只增不改**：不得删除/重命名 §5.1 的 id/class；新增节点优先作为现有节点的子节点。
2. **不泄露隐藏信息**：DOM 中不得出现对手手牌牌面、`card.id`、`faceCode`；对手只允许 `handCount` 与卡背。
3. **状态用 `data-*` + class 双写**：class 负责视觉，`data-*` 负责测试/状态机；两者不得表达不同含义。
4. **文本节点可替换**：`#turn-stamp`、`#phase-label`、`#result-meta` 的文本更新不得重建父容器。
5. **不重建 `#hand`**：M4 保留 `root.replaceChildren` 的手牌更新方式，但 UNO 按钮在窗口期内必须原地更新（见 §7.4）。
6. **aria**：装饰卡背 `aria-hidden="true"`；对手 `aria-label` 含准确牌数；`#result-win-card` 的 `aria-label` 为「获胜牌：{cardLabel}」；无牌时 `aria-hidden="true"`。
7. **无外部资源**：不新增 CDN、Google Fonts、远程图片；牌面/卡背继续用 `apps/web/cards/*.png` 与 `assets/card-back.svg`。
8. **Demo 隔离**：`review-assets/v2-ui-prototype/*` 不复制进 `apps/web`；Demo 的类名（`.seat-north`、`.hand-label`、`.match-tools` 等）不进入生产契约。

## 7. UNO 契约

### 7.1 难度映射

| 难度 | key | 窗口时长 | 环时长 |
| --- | --- | --- | --- |
| 休闲 | `casual` | 10000ms | 10s |

| 真实 | `realistic` | 6000ms | 6s |
| 骨灰级 | `hardcore` | 4000ms | 4s |

禁止在 CSS/HTML/多个 JS 文件里重复写 4000/6000/8000/10000。

### 7.2 显示条件

UNO 按钮仅在以下条件**同时成立**时渲染：

```js
view.human.hand.length === 1
&& view.phase === 'uno-window'
&& view.human.canCallUno === true
&& legalActions.some(a => a.type === 'CALL_UNO')
```

抓 UNO 按钮仅在 `CATCH_UNO` 合法且 `human.canCatch.length > 0` 时渲染；两者不得同时出现在同一座位。

### 7.3 单机数据流

1. 玩家出牌后剩 1 张且未喊 UNO → 引擎进入 `uno-window`。
2. `engineMode` 读取 `state.config.aiDifficulty`，查表得 `windowMs`。
3. `document.documentElement.style.setProperty('--uno-window-ms', `${windowMs}ms`)`。
4. `window.UnoApp.render(view)`；`hand.js` 创建 `.uno-button > .uno-countdown`。
5. 计时器到期：
   - 若下一位是 AI：按现有 `scheduleAi` 推进（窗口关闭由引擎裁决）；
   - 若下一位是人类：保留现状，不伪造动作；环结束只改变 UI 状态（见 §7.5）。
6. 玩家点击 UNO → 现有 `CALL_UNO`；点击抓人 → 现有 `CATCH_UNO`；不新增动作类型。

### 7.4 环的 DOM/CSS

```html
<button class="btn uno-button" data-action-id="..." data-action-type="CALL_UNO"
        data-window-state="open" aria-label="喊 UNO">
  <span class="uno-countdown" data-window-key="uno-2-37" aria-hidden="true"></span>
  <span class="uno-label">UNO!</span>
</button>
```

```css
.uno-button { position: relative; }
.uno-countdown {
  position: absolute;
  inset: -5px;
  border-radius: 999px;
  background: conic-gradient(var(--v2-gold) calc(var(--uno-progress, 1) * 360deg),
                             transparent 0);
  -webkit-mask: radial-gradient(farthest-side, transparent calc(100% - 4px), #000 0);
          mask: radial-gradient(farthest-side, transparent calc(100% - 4px), #000 0);
  animation: uno-ring var(--uno-window-ms, 4000ms) linear forwards;
}
@keyframes uno-ring { from { --uno-progress: 1; } to { --uno-progress: 0; } }
```

> `@property --uno-progress` 若在目标 Chromium/Electron 不支持，M5 改用 SVG `stroke-dashoffset` 或 `conic-gradient` + `transform: rotate()` 遮罩方案；不得退回每秒重绘。

规则：

1. `.uno-countdown` 类名保留（现有断言依赖）；可同时加 `.uno-ring`。
2. 同一 `data-window-key` 内重复 render 不得重启动画；M5 需在 `hand.js` 中复用按钮节点或设置负 `animation-delay`。
3. 环不接收指针事件；按钮命中区域 ≥44px。
4. 环颜色只用 `--v2-gold`；UNO 按钮底色沿用红色系。
5. `aria-label` 固定「喊 UNO」；不每秒更新 `aria-live`，避免读屏刷屏；窗口开启时由 `#hint-bar` 提示一次。

### 7.5 到期与联机边界

- **默认行为（M1 锁定）**：环结束后，`.uno-button` 加 `data-window-state="expired"`，隐藏按钮/环；`#hint-bar` 显示「UNO 窗口已结束」1.2s；**不提交任何动作**。引擎/服务端仍按既有状态机在下一位行动时关闭窗口或结算罚牌。
- **单机**：`engineMode` 的 4s 定时器改为难度时长；到期后按现有逻辑推进 AI/等待人类。若下一位是人类且不行动，窗口保持——与 v1.3.0 一致，不是 v2 新增缺陷。
- **联机**：客户端从房间配置读取难度，映射到环时长；窗口开/关仍由服务端状态机裁决；**不新增服务端超时罚牌**、不改 WebSocket 协议、不新增动作。若后续要求「超时自动罚牌」，必须单独立项修改 `packages/game-core` / 服务端，并重新评审边界。
- **AI 参与**：AI 是否喊/抓仍由引擎在出牌时掷概率；UI 不新增 AI 定时抓人。难度只影响窗口呈现与单机推进节奏，不改变 AI 概率表。
- **测试模式**：`?test=1` 继续使用 120ms 短窗口；不得让测试模式写入难度映射。

### 7.6 UNO 验收

- 手牌 0 张：无 `.uno-button`。
- 手牌 2 张以上：无 `.uno-button`。
- 手牌 1 张、`uno-window`、`canCallUno=true`：有且只有一个 `.uno-button`，环存在。
- 手牌 1 张但 `canCallUno=false`：无按钮；其他座位按 `CATCH_UNO` 显示。
- 休闲/简单/真实/骨灰级：`--uno-window-ms` 分别为 10000/8000/6000/4000。
- 重复 render 3 次：环不重启（`data-window-key` 不变）。
- `html[data-animation="false"]` 或 reduced-motion：环静止，按钮可见，提示仍可读。
- 联机：对手手牌牌面仍不可见；`CATCH_UNO` 权限不变。

## 8. 结算与获胜牌契约

### 8.1 数据来源

| 场景 | 获胜牌来源 | 显示 |
| --- | --- | --- |
| `result.reason === 'empty-hand'` 且 `winnerSeat !== null` | `view.table.discardTop` | 飞入 `#result-win-card`；标题 `{name} 获胜` |
| `result.reason === 'deck-empty'` | 无「最后打出」语义 | 静态空槽/牌堆图标；标题含「牌堆耗尽」与赢家名 |
| 平局（`winnerSeat === null`） | 无 | `#result-win-card[hidden]`；标题「平局」 |
| 源节点不存在/尺寸为 0/屏幕已隐藏 | 使用 `lastTableCardRect` 缓存；缓存也没有 | 静态卡牌（使用 `discardTop`）淡入 |
| reduced-motion / 动画关闭 | 降级 | 静态卡牌淡入，无飞行 |

**不改协议**：`discardTop` 已存在于 `GameView.table`（`packages/game-core/src/public-view.ts`），联机视图同样下发；不新增 `lastWinningCard` 字段，不读取对手隐藏手牌。

### 8.2 结算头部

```html
<header class="result-header">
  <p class="result-kicker">本局结算</p>
  <h2 id="result-title">你 获胜</h2>
  <p id="result-meta">人数 4 · 手数 38 · 用时 164 秒 · 行动 164</p>
</header>
```

- `#result-title`：`{winner.name} 获胜` / `平局`；去 emoji；必须包含胜者名，兼容现有断言。
- `#result-meta`：`人数 {players.length} · 手数 {result.turns} · 用时 {round(durationMs/1000)} 秒 · 行动 {result.actions}`；`deck-empty` 追加 ` · 牌堆耗尽`。
- 不使用恒为 1 的「局数」；若用户要求保留，改为「局数 1/1」，但 M1 默认不显示。
- 保留 `.result-summary` 统计卡（总行动/出牌/摸牌/叠牌/UNO/挑战）与 `#result-charts` 四张图；只改布局，不删数据。
- 删除/不新增「按事件类型查看本局行动构成」；图表标题保留「每位玩家操作次数」「全体操作构成」「剩余手牌构成」。

### 8.3 飞牌

1. **先取源**：`render()` 在切换屏幕前（`game → result`）读取 `#discard-pile` 最后一个 `.card` 的 `getBoundingClientRect()`，存入动画模块的 `lastTableCardRect`；若当前已是结算屏或 rect 为空，使用缓存的最后一次牌桌 rect。
2. 结算 render 后，读取 `#result-win-card` 的 `getBoundingClientRect()`。
3. 克隆节点（`cloneNode(true)`），加 `.result-fly-card`，`position: fixed`，从源 rect 到目标 rect，`transform` + `opacity`，520ms。
4. 源节点加 `.is-flying`（`opacity: 0`），飞完移除克隆并恢复源节点。
5. 目标槽在飞行期间保持占位（`visibility: hidden`），避免布局跳动。
6. 转场期间 `#result-screen` 加 `data-transition="running"`；重复点击「再来一局/回大厅」被忽略，520ms 后解除。
7. 平局/无牌：不飞，静态显示 `#result-win-card[hidden]` 或占位。
8. 刷新/直接进入结算、联机重连或 rect 为 0：不飞，走静态降级。

> 不得在 `.screen` 切换为 `display: none` 后再读取源 rect；这是 M6 的主要坑位。`render.js` 的切换顺序为“先取源、再切屏、再渲染结算”。

### 8.4 科技感胜利填充

- 只作用于 `#result-title` 文本与 `#result-win-card` 边缘光；不大面积铺背景。
- 渐变四色：`--v2-win-red` → `--v2-win-gold` → `--v2-win-green` → `--v2-win-blue`，`background-clip: text`；不支持时回退 `color: var(--ink)`。
- 一次 520ms 的亮度扫过；不循环、不闪烁；reduced-motion 静态渐变。
- 标题与统计各自独立布局槽；420 下标题最多两行，统计换行不重叠。

### 8.5 结算验收

- 真人获胜：标题含「你 获胜」；获胜牌 = 最后一张；飞入不遮标题；`.result-row.is-winner` 有「出完手牌」。
- AI 获胜：标题含 AI 名；获胜牌正确；手牌隐私不泄露。
- 平局：标题「平局」；无获胜牌槽；图表与统计仍完整。
- 牌堆耗尽：标题含「牌堆耗尽」；无飞牌；赢家行「手牌最少获胜」。
- 刷新/直接进入结算：静态降级可读。
- reduced-motion/动画关闭：无飞牌、无循环动画。
- 420：标题/统计/获胜牌不重叠，页面不横溢。
