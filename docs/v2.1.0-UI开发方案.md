## 一、改什么（范围、文件、边界）

### 1. 本次方案的硬约束

- **视觉基线不动**：radical 近黑基底 + 荧光绿点缀是唯一主题，不引入主题切换、皮肤市场或浅色模式；v2.1 所有新增视觉必须在 radical token 体系内表达。
- **红线全部继承**：`packages/game-core`、`packages/ai`、GameView/UiAction/事件类型、WebSocket 协议、桌面壳零改动；出牌只点手牌；视图隔离与脱敏不放宽。
- **动效纪律不变**：只为状态变化服务，一次性播放；不引入持续漂浮/闪烁/大面积粒子作为默认背景；所有新动效支持动画关闭与 `prefers-reduced-motion` 静态降级；重复 render 不得重启已完成动画。
- **对手手牌不泄露**：卡背只表达规模，精确牌数仍由文字提供；联机视角隔离断言不放宽。
- **战绩与台词只读本地**：战绩页只消费 `localStorage` 既有 `games/wins` 等本地数据；台词库为前端内容表，按事件类型选取，不新增协议字段、不做联机人设同步。
- **不做**：M11/M12 跨网公网联机、文字聊天、账号/排行榜/数据库、联机智谱决策、对局快照、主题市场、规则变体编辑器。

### 3. 明确不改的代码边界

- 不修改 `packages/game-core/src/*`、`packages/ai/src/*`、`apps/server/src/*`。
- 不修改 GameView、UiAction、事件类型、WebSocket 协议与公开视图字段。
- 不改 radical 主题 token 值与 `#app::before` 网格纹理等已发布视觉签名。
- 不恢复「不做」清单内的任何能力；发现规则/协议缺陷时停下记录，不用 UI 改动绕过。

### 4. M1—M8 阶段分布

> 执行编号沿用 **M1~M8**（与 v2.0.0 同构）。M2~M5 为四个可独立验收的功能切片，顺序可按用户指令调整。

#### M1：视觉契约与范围收敛

- **目标**：把 v2.1 范围固定为可实现的契约；用户勾选/否决候选项。
- **文件**：新增本文档；范围确认后产出 [`v2.1.0-M1-视觉契约.md`](./v2.1.0-M1-视觉契约.md)（新增锚点/属性/动效表/文案表，格式对照 v2.0.0 契约）；更新 `docs/开发进度.md`。
- **代码边界**：不改生产 HTML/CSS/JS。
- **验收**：范围逐项有「做/不做」结论；新增 DOM 锚点、动效降级策略、截图场景与回滚边界完成评审。
- **产出（2026-10-26）**：本方案已写入；范围五问已由用户确认（§二.1），契约已产出（§0~§9），**M1 关闭**。

#### M2：对手手牌可视化进阶（M13-04 + 卡背 N 张）

- **目标**：对手手牌从「1~5 张封顶示意」升级为规模感知更准确的卡背堆，并为数量变化增加一次性反馈。
- **文件**：`apps/web/js/ui/players.js`、`apps/web/styles/cards.css`、`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`。
- **可视化**：按 `handCount` 分档渲染（1~5 张逐张，6+ 张溢出徽标「+N」，≥10 张满堆样式，详见契约 §2.1），卡背随数量增减做一次 240ms 内的推入/弹出反馈；当前回合座位维持静态上移（M13-04 原约定）；密度设置入口不做（M1 结论），自动分档。
- **可能问题**：10 人局 + 满堆卡背在小屏拥挤；重复 render 触发动画重启。
- **修改规则**：数量分档与封顶值进契约；动画用 `data-hand-count` diff 触发一次；420 宽度维持可隐藏卡背但保留精确牌数。
- **验收**：0/1/5/6/12 张边界正确；2/4/10 人、单机/联机、四档宽度无重叠不溢出；动画关闭走静态卡背。

#### M3：牌面动效升级（出牌飞行 + 发牌动画）

- **目标**：补齐 v2.0.0 后候选项中的「复杂牌面飞行、完整发牌动画」，提升出牌与开局反馈。
- **文件**：`apps/web/js/animation/*`、`apps/web/styles/animations.css`、`apps/web/styles/cards.css`、`scripts/verify-ui.mjs`。
- **可视化**：出牌时手牌克隆体飞向弃牌堆（复用 M6 结算飞牌的降级链思路）；开局按座位顺序一次性发牌动画；摸牌一张短距离滑入。全部一次性播放，总时长受现有动画时长 token 约束。
- **可能问题**：联机事件乱序/补发导致重复飞行；动画队列与输入锁交互；性能。
- **修改规则**：以事件队列为唯一动效来源，状态补发不重播；飞行源缺失/`prefers-reduced-motion`/动画关闭走静态降级；只用 transform/opacity，完成后清理节点。
- **验收**：出牌/发牌/摸牌动效各有一次且可中断；重复 render 不重启；perf FPS 仍 60；降级路径可读性等价。

#### M4：台词库与表情增强（M6-03）

- **目标**：AI 台词从零散硬编码收敛为内容表，并支持按事件类型/难度选取；表情气泡增强。
- **文件**：新增 `apps/web/js/ui/lines.js`、`apps/web/js/ui/players.js`（气泡接入）、`apps/web/styles/components.css`、`scripts/verify-ui.mjs`。
- **可视化**：出牌、+2/+4、挑战、抓 UNO、获胜等事件映射到台词组；同一事件短时间内不重复同句；表情气泡保留现有 TTL 与 aria 机制。
- **可能问题**：台词过多干扰牌桌信息优先级；重复 render 重启气泡。
- **修改规则**：台词为纯前端内容表（可后续扩充）；默认低频、可被设置页开关关闭（复用现有设置存储契约，只增键不改键）。
- **验收**：各事件台词可触发且不遮挡座位信息；关闭开关后零台词；单机/联机行为一致且不新增协议字段。

#### M5：本地战绩页（M6-04）

- **目标**：把既有本地战绩（`games/wins`）做成只读战绩页，作为大厅次级入口。
- **文件**：新增 `apps/web/js/ui/records.js`、`apps/web/index.html`、`apps/web/styles/layout.css`、`apps/web/styles/components.css`、`scripts/verify-ui.mjs`。
- **可视化**：大厅次级入口「战绩」；战绩页显示总局数/胜率/最近对局列表（时间、人数、名次）；无数据时空态文案。
- **可能问题**：现有本地存储字段不足以支撑「最近对局」明细。
- **修改规则**：既有 `uno:stats` 键不迁移不改键；新增独立键 `uno:records` 记录最近对局明细（M1 已确认允许，只写本地、不进协议，详见契约 §5）；不改红线「结算无分数」。
- **验收**：入口可键盘到达；空态/有数据态可读；420 宽度不溢出；退出战绩页回大厅状态不丢失。

#### M6：响应式、无障碍与性能收口

- **目标**：把 M2~M5 增量收敛进 radical 体系，覆盖触控、键盘、低动效与四档宽度。
- **文件**：`apps/web/styles/*`、`scripts/verify-ui.mjs`、`scripts/verify-online.mjs`。
- **代码边界**：不以响应式分支复制逻辑；不为装饰层加可访问名称。
- **验收**：420/760/1024/1440 四档 + 2/4/10 人全过；新动效全部有静态降级；焦点环/触控 ≥44px/aria 规则复测通过；perf FPS 60。

#### M7：协同测试、回归与版本号统一

- **目标**：确认增量未破坏规则、联机与桌面边界，并完成 v2.1.0 发布准备。
- **文件**：验证脚本、`package-lock.json`、`apps/server/package.json`、`docs/开发进度.md`、`CHANGELOG.md`。
- **范围**：全仓版本号统一 2.1.0（含 package-lock/server 遗留的 1.3.0 条目）；顺带跟进 GitHub Actions CI 失败定位；质量基线全量复跑。
- **代码边界**：只修复由 v2.1 增量直接引入的回归；CI 与遗留断言问题单独记录，不扩大范围。

#### M8：发布 v2.1.0

- **目标**：tag `v2.1.0` 推送、GitHub Release、桌面安装包打包上传、文档同步。
- **验收**：`npm test`、`typecheck`、`lint`、`verify:ui`、`verify:online` 全过；桌面端按可用环境完成启动/静态资源检查；CHANGELOG、截图、进度台账同步。

### 2. 开发中可能出现的问题

- 卡背堆从封顶 5 张改为分档渲染后，`data-hand-count` 断言与 CSS 选择器需要同步扩展，防止旧断言锁死新分档。
- 出牌飞行在联机补发/乱序事件下可能重复播放；必须以事件队列消费为唯一触发点。
- 台词库内容增长后需防气泡互相覆盖与 aria-live 刷屏；保持现有 TTL 与清理机制。
- 战绩页读取 localStorage 需容错损坏数据（try/catch + 空态降级）。
- 新增 `lines.js`/`records.js` 需遵循现有 `window.UnoApp` 五 API 契约与模块挂载方式，不引入构建体系变化。
