## 3. 做出了什么效果

### v1：能安静打完一局

- 玩家可在大厅选 2~10 人、四档 AI、智谱/本地/自动、+4 挑战；点「开启对局」后发牌动画飞向各座位。
- 规则按手感做了取舍并写成设置项：**宽松叠牌**（+2/+4 任意互叠、累计摸牌）、**主动摸牌摸到能打为止**、2 人特殊规则、牌堆耗尽策略、UNO 罚牌 1/2/3 张、+4 挑战。断网时本地 AI 照常出牌。
- 15 类事件动效（只改 transform/opacity，队列串行播放）、16 类 WebAudio 现场合成音效、动画开关与正常/快速两档、`?slow=1` 观察、reduced-motion 静态降级。
- 结算**无分数**，只给每位玩家操作统计、全体动作构成、剩余手牌颜色三张纯 CSS 图表。
- 局域网联机：6 位房间码、改名、AI 补位、掉线重连、房主移交、再来一局、表情气泡（5 条后冷却 2s）；桌面版 UDP 自动发现附近房间，可手动 `IP:端口` 兜底。
- 桌面版：内嵌随机端口服务，不需另装 Node.js；设置页自填智谱 Key（DPAPI 加密），NSIS 当前用户安装、免管理员。

### v2.0.0：从「牌桌」变成「控制面」

- **M2** 品牌收敛为 `UNO Local` + 版本号，统一「开启对局」，顶栏加品牌条。
- **M3** 椭圆牌桌 + 座位圆周锚点（2~10 人角度表）、`#turn-stamp` 常显当前行动者、`#phase-label` 只在特殊阶段出现；10 人桌 1440/1024 都不重叠。
- **M4** 悬浮手牌坞、手牌卡宽六档、`#hand[data-count]` / `.card[data-state]` / `#action-bar[data-phase]`、触控目标 ≥44px。
- **M5** UNO 按钮只在「1 张 + 窗口 + 合法」时出现，conic-gradient 金环按难度 10/8/6/4s，`data-window-key` + 负 animation-delay 防重复渲染重置；动画关闭时静态降级。
- **M6** 获胜牌飞入结算槽 520ms、四色渐变标题一次亮度扫过、平局/牌堆耗尽/缺源静态降级。
- **M7** 荧光绿焦点环、CDP 真实键盘路径、四档宽度断言、FPS 60。
- **风格重塑**：近黑 `#090d0b` + 荧光绿 `#d9ff4b` + 36px 全屏网格纹理，令牌名不变只换值。

## 4. 遇到的 Bug 与坑位（重点档案）

### 4.1 布局与一屏

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| M3 圆桌竖向溢出 7px | `.arena` 固定 `56vh` 撑破视口 | 中行改 `minmax(0,1fr)`、`#game-screen` `100dvh` 弹性行；arena `height:100%; max-height:var(--v2-arena-h)` |
| N3 ≤1080 单列后「开启对局」沉出首屏 | 巨字三行把 copy 区撑高 | 窄屏巨字 `display:inline` 单行 + clamp 三档字号 + 压缩 copy；六档视口实测按钮 top |
| N4a ≤420 手牌区 `min-height` 变 0 | `#hand{min-height:0}` 未加 `@media(min-width:761px)` 作用域，覆盖了 168px 断言 | 加作用域限定 |
| N4a UNO 按钮被缩小到 12px | `.action-stack .btn` 连 `.uno-button`（同为 `.btn`）一起命中 | 单独 `#action-bar.action-stack .uno-button{font-size:22px;min-height:64px}` 覆盖 |
| N4a 手牌坞断言失败 | 文档流化时想把渐变底设 transparent / 去掉安全区 padding | `.hand-dock` 渐变底 + `padding-bottom≥8` 是 M4 硬依赖，不能动 |
| 1024 宽横向溢出 48px | 大厅水印牌的位移 + 旋角把 `documentElement.scrollWidth` 撑到 1072 | ≤1080 收掉 `transform`（`!important`）、改左上定位 |
| 巨字断言取不到字符串 | 三行分别在 `span/em`，`textContent` 无空格 | 断言按 `span,em` 逐块 `join(' ')` |
| headless 截图「420 宽溢出」是假象 | `--window-size` 不被遵守（实际渲染 497 宽） | 诊断一律用 CDP `Emulation.setDeviceMetricsOverride` |

### 4.2 启动与资源加载

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| **首次启动先闪完整 UNO 字形再清空重写** | `.boot-ink path` 无初始 dasharray，CSS 首帧画出完整字形；`boot.js` 是 ESM（defer），晚于首帧 | CSS 预设 `stroke-dasharray/dashoffset:2400`；`boot.js` 改 `</body>` 前同步执行的经典 IIFE，自读 `uno:settings` |
| 遮罩退场时露出空壳/缺卡面 | 大厅随机卡面还没解码 | 卡面预解码后挂 `data-ready`，`waitForApp()` 一并等待（2.2s 兜底） |
| 6 人轮转断言偶发失败 | 采样窗 5s 短于智谱单次决策 3.8s | 采样窗 5s → 9s |
| 卡面解码偶发 106/107 张 | 图片并发解码抖动 | 复跑即可，非代码缺陷 |
| N4a `railNo` 引用异常 | 属性名与 DOM const 同名造成遮蔽 | 断言直接用 trim 后的字符串字段做 `^\d{1,3}$` 校验 |

### 4.3 图标与打包（2026-11-07 集中踩到）

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| **exe 图标有白角** | CDP `captureScreenshot({omitBackground:true})` 单独用无效，PNG 是 RGB（colortype=2）无 alpha，四角纯白不透明 | 先 `Emulation.setDefaultBackgroundColorOverride({color:{r:0,g:0,b:0,a:0}})`；组装前自检每尺寸四角 `alpha=0` |
| 小尺寸仍可能白角 | PNG-only ICO 在旧渲染路径下 alpha 被忽略 | 16/24/32/48 改 **32bpp DIB + 1bpp AND mask**（`biHeight=2h`），64/128/256 用带 alpha PNG |
| 桌面一直显示旧图标 | Windows 图标缓存按路径索引，不是文件没换 | `SHChangeNotify(SHCNE_ASSOCCHANGED\|SHCNE_UPDATEITEM)` + `ie4uinit.exe -show`；或新文件名副本；彻底清缓存需重启 explorer（脚本 `C:\Users\hw\Desktop\refresh-uno-icon.cmd`，未擅自执行） |
| 大厅「背板」白色方块 | 卡面 PNG 个别角残留白色不透明像素（`G2` 右上、`R7` 左下，`process-cards.py` 抠图不干净） | 显示层套 squircle 遮罩裁掉；**牌面素材不可修改是红线**，不允许批量改 PNG |
| 加遮罩后牌的投影消失 | CSS `filter` 先于 `mask` 生效，mask 裁掉元素自身 filter 输出 | `drop-shadow` 上移到 `.lobby-deck` 容器 |
| electron zip 下载 ~70KB/s | 默认从 GitHub 拉 | `-c.electronDist=<repo>/node_modules/electron/dist` 用本机已解包 Electron |
| `EBUSY: unlink .../app.asar` | 旧 `release/win-unpacked/resources/app.asar` 被系统锁 | `-c.directories.output=<全新目录>`，再把成品覆盖回 `release/`；旧目录 safe-delete 也删不掉 |
| 临时脚本污染 `npm run lint` | `review-assets/` 未进 ignore | `eslint.config.js` 加 `review-assets/**` 与 `**/release-*/**` |
| Electron 首次运行下载失败 | 网络 | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` + `node node_modules/electron/install.js` |
| `verify:desktop` 沙箱 SKIP | 真实 Electron GUI 以 `0x80000003`/`0xC0000005` 退出 | SKIP 不算通过；真机 `UNO_REQUIRE_DESKTOP=1` |

### 4.4 验收、环境与工程

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| `npm test` 恒 334/335 | 本机安全策略拦截 `esbuild.exe`（winapi error #5），`web-engine-bundle` 用例写临时文件被拒 | 已知环境问题，与代码无关；`npm run dev/start` 的 pre 钩子可绕过，直接 `npm run start -w @uno/server` |
| 启动脚本被火绒误报 `PS.NetLoader` | PowerShell 自提权/隐藏窗口 | 保持纯 `.cmd`，不自提权 |
| `verify:ui` 端口冲突 / 定时器节流 | 9333、9334；后台标签页定时器节流 | 端口固定；冷却断言用轮询 |
| WS 集成测试偶发超时 | 默认 5s 不够 | 显式传 `{ timeout }` |
| 本机 bash 环境 | 部分 coreutils 曾缺失；WorkBuddy 注入 `NODE_OPTIONS` 安全删除 shim、子进程 spawn 偶发 EBUSY | 复现用户环境时 `unset NODE_OPTIONS CODEBUDDY_SAFE_DELETE_*`，必要时 `--ignore-scripts` |

### 4.5 联机、桌面壳、安全

- `unoWindow.canCatch` 是**可被抓的目标**不是抓人者名单；联机 `config.humanSeat=-1`、单机为 0，判断「我」必须用视角座位；`drawnThisTurn` 只在 `currentSeat === seat` 下发。
- 开局座位随机、起手动作牌由首位承受，手牌可能 >7，断言不能写死 7。
- 房间只在服务进程内存；IP 以 `/api/health` 为准；防火墙规则 `UNO-Local-3000`；UDP `41234`、2 秒广播、TTL 7 秒、只广播 `lobby`。
- `main.ts` 必须先 `import './environment.ts'` 再导入 server；`listen(0)` 后 health 用实际端口；桌面专属 UI 一律 `window.unoDesktop` 分流。
- `safeStorage` 只能在 `app.whenReady()` 后；先 `loadStoredApiKey()` 再 `startUnoServer()`；`zhipuClient.isConfigured` 必须是 getter；IPC 永不回传明文。
- `joined.host` 必须写 `host:port`；房主迁移只由 `RoomManager.promoteHost()` 决定，原房主重连不夺回；`stopUnoServer()` 先 `notifyShutdown()` 等 150ms，WS 握手 8 秒，旧 socket 用 `socket === ws` 守卫。
- 已修：UNO 窗口按座位过滤、联机抓 UNO 误判、`drawnThisTurn` 视图泄露、AI 台词上一位残留、常驻提示条冗余、操作栏出牌按钮、正常回合冗余状态文字。

## 5. 关键决策与红线

1. **规则**：宽松叠牌、摸到可出为止、UNO 单击即喊、窗口 10/8/6/4s、结算无分数、挑战只给人类看 AI 手牌。
2. **隔离**：`GameView` 是 UI 唯一数据源，`window.UnoApp` 五个 API 与 DOM 锚点**只增不改**；联机按座位脱敏、服务端权威。
3. **v2 边界**：不改 `packages/game-core`、`packages/ai`、GameView/UiAction/事件类型、WebSocket 协议与桌面壳逻辑。
4. **牌面素材不可修改（2026-11-07 用户再次确认）**：`apps/web/cards/*.png` 与 `assets/card-back.svg` 保持原样，白角只能在**显示层用遮罩**处理；批量去背方案已废弃。
5. **连续曲率圆角（2026-11-07 硬性规定，优先级最高）**：一切 UI 圆角用 squircle，禁止普通 `border-radius` 圆弧；统一资源 `apps/web/assets/squircle.svg`、token `--ui-squircle`；详见 [`UI优化方案-待开发.md`](./UI优化方案-待开发.md) §0 与 [`开发约定.md`](./开发约定.md) §6。**同日追加例外（优先级更高）**：「数据显示的卡片不用做圆角」→ 右栏数据面板保持直角（0 圆角 + 1px 边框，不套遮罩），U4 不得改回圆角。
6. **不做**：台词库、自定义表情/持久化/文字聊天、对局快照、跨网公网联机（M11/M12 暂缓）、计分。
7. **节奏**：未经用户明确说「开始 Mx / Ux」不得写实现代码；纯文档整理无需指令；一个模块做完即停手等验收，不顺手重构。
8. **汇报 / 自检 / 提交（2026-11-07 硬性规定，优先级最高）**：每次开发完输出**只包含三段**（开发了什么 / 能实现什么样的效果 / 还剩什么）；每次改完文件必须**自行验证无 bug** 才汇报（验证不单列成段）；用户批准下一步开发后**先自动 commit + 打 tag，再开工**，不做 push。首次批准先分组提交历史存量改动并打 `u0-baseline`。全文见 [`开发约定.md`](./开发约定.md) §7、[`开发进度.md`](./开发进度.md) §4 第 12 条。
