# UNO UI v2.0.0 开发计划

> 版本目标：在 v1.3.0 可玩、可联机、可打包的基础上，完成一次面向牌桌体验的 UI 体系升级。
> 计划类型：UI/交互版本，不重写规则引擎、AI、联机协议或桌面壳。
> 计划状态：方案阶段。
> 编写日期：2026-10-23。

## 1. 当前基线

### 1.1 已完成能力

当前项目已经具备 v2.0.0 所需的稳定功能底座：

- M0~M10 已完成，当前版本为 v1.3.0。
- 单机真实对局闭环：大厅、牌桌、手牌、AI 回合、UNO、+4 挑战、叠牌、结算。
- AI 支持本地决策、智谱混合决策和失败降级。
- 2~10 人布局已存在，包含单机 AI、局域网联机、视角座位和房间重连。
- Electron 桌面版、NSIS 安装包、UDP 附近房间和手动主机地址已实现。
- 动效队列、动画开关、prefers-reduced-motion、设置弹窗、预置表情和挑战展示已有基础。
- 质量基线：npm test、typecheck、lint、verify:ui、verify:online 已有正式验证路径。

### 1.2 当前限制

- 牌桌中央状态的层级不够强，玩家需要从多个小信息中判断当前回合和下一步动作。
- M13 已提供 1~5 张对手卡背与牌数文字，但卡背状态联动、动效与整体视觉统一仍可继续。
- 大厅配置项较多，开始游戏、设置、战绩、局域网入口的优先级还可以进一步拉开。
- 移动端已经响应式，但手牌、操作栏、提示和顶部状态之间的空间关系仍需要专门设计。
- 结算页数据完整，信息密度偏高，胜者结论和操作统计之间的层级还不够明显。
- 当前主要使用系统字体和深绿色牌桌视觉，缺少一套可复用、可扩展的 UI token 体系。

### 1.3 M13 状态核对

仓库当前可见状态：

- docs/M13-对手手牌可视化.md 已标记 **MVP 已完成（2026-10-23）**。
- apps/web/js/ui/players.js 已渲染 `.opponent-hand`，并按 `handCount` 生成 1~5 张卡背；头像、名字、牌数、上一张出牌、UNO 状态和台词保持。
- 当前代码已包含 `.opponent-hand`、`.opponent-hand-card`、`data-hand-count`、`data-visible`、`data-layout="fan"`。
- view.players[*].handCount 已存在，未扩展 GameView、服务端或 WebSocket 协议。

V2-00 可直接在 M13 MVP 的基础上做统一视觉与 token 化；不要让“已实现”“进行中”“未开始”同时存在于不同文档中。

## 2. v2.0.0 产品目标

v2.0.0 的目标不是增加规则数量，而是让玩家在 1 秒内回答三个问题：

1. 现在轮到谁？
2. 对手大约还有多少牌？
3. 我现在可以做什么？

本版本的体验方向定为：**竞技桌面 2.0**。

它保留深绿色牌桌和真实 UNO 卡牌作为核心识别资产，通过更明确的回合指示、对手手牌可视化、动作优先级和响应式操作区提升可读性。视觉重点集中在牌桌和牌面，不引入完整主题系统、账号系统或规则重构。

### 2.1 版本签名元素

v2.0.0 只设置两个强记忆点：

- **中央回合环**：围绕弃牌堆或牌桌中心表达当前行动者、方向和当前颜色。
- **对手手牌堆**：在对手座位框中以 1~5 张缩小卡背表达手牌规模，精确数量仍由文字提供。

其他区域保持克制，避免每个状态都使用大面积发光或动画。

### 2.2 不改变的能力

- 不改 packages/game-core 的规则、状态机和结算逻辑。
- 不改 packages/ai 的候选动作、难度、记牌和混合决策逻辑。
- 不改 GameView、UiAction、事件类型和服务端公开视图契约。
- 不改 WebSocket 房间协议、座位隔离和重连流程。
- 不恢复 M11/M12 跨网公网联机。
- 不引入前端框架、数据库、账号、排行榜或新的构建体系。

## 3. 视觉与交互原则

### 3.1 信息优先级

牌桌上的视觉优先级固定为：

1. 当前行动者和玩家可执行动作。
2. 弃牌堆、当前颜色、叠牌/挑战/UNO 等特殊阶段。
3. 对手手牌规模、UNO 状态、上一张出牌。
4. 事件日志、AI 台词和装饰性动效。

### 3.2 视觉基调

建议沿用深绿色牌桌，但重新整理 token：

| 角色 | 建议方向 |
| --- | --- |
| 桌面底色 | 深森林绿，保持长时间观看的舒适度 |
| 主要文字 | 接近白色，保证牌桌上的高对比度 |
| 次要文字 | 低饱和青绿色，用于说明和历史信息 |
| 主操作色 | 暖黄色，用于开始、UNO、当前回合和关键动作 |
| 危险状态 | 红色，用于退出、罚牌和失败反馈 |
| 辅助状态 | 蓝色或青色，用于方向、联机和信息提示 |

颜色不能成为唯一状态来源。当前颜色、UNO、当前回合和错误状态都必须同时有文字、位置、边框或图形变化。

### 3.3 动效原则

- 只为状态变化服务：回合切换、牌数变化、UNO 窗口、关键动作反馈。
- 不增加持续漂浮、持续闪烁或大面积粒子作为默认背景。
- 所有新增动效都要支持动画关闭和 prefers-reduced-motion。
- 重渲染不能导致旧台词、表情、弹窗或事件队列异常重启。

## 4. 版本范围

### 4.1 V2-00：基线同步与设计契约

目标：在开始视觉改造前锁定 M13 状态、DOM 锚点和截图基线。

工作内容：

- 记录当前 M13 实际状态，统一 开发进度.md、开发计划.md、M13 文档和实现状态。
- 固定桌面、平板、移动端验收尺寸：1440×900、1024×768、760×900、420×844。
- 固定 2/4/10 人对局、正常回合、AI 思考、UNO、+4 挑战、结算、联机视角等截图场景。
- 定义 v2.0.0 的稳定 DOM 类名和 data-* 属性，避免视觉迭代反复修改引擎契约。
- 建立 token 表：颜色、间距、层级、牌桌中心尺寸、卡背尺寸、状态色、焦点样式。

交付物：设计契约、截图基线、M13 状态同步记录。

### 4.2 V2-01：M13 对手手牌可视化

目标：完成 M13 MVP，并作为 v2.0.0 的第一个可验证 UI 切片。

实现范围：

- 读取 view.players[*].handCount，不新增数据字段。
- 对手座位框左下角显示 1~5 张卡背，0 张不显示，6+ 张封顶显示 5 张。
- 保留右上角 lastPlayed、右下角 UNO 状态和现有牌数文字。
- 固定 DOM 契约：.opponent-hand、.opponent-hand-card、data-hand-count、data-visible、data-layout。
- 卡背 aria-hidden=\"true\"，准确牌数继续由对手座位的 aria-label 和文本提供。
- 1024、760、420 三档响应式降级；420 宽度可以隐藏卡背，但不能隐藏准确牌数。
- 动画关闭和 reduced motion 下保留静态卡背，不运行脉冲和持续动画。

本阶段不做：完整 N 张、卡背皮肤、显示密度设置、替换上一张出牌、复杂摸牌动画。

验收重点：卡背不遮挡名字、牌数、UNO、上一张出牌、表情气泡和手牌区；联机视角中不显示自己的对手卡背。

### 4.3 V2-02：牌桌状态与回合层级

目标：让当前回合和特殊阶段在牌桌上拥有稳定、清晰的视觉中心。

工作内容：

- 在牌桌中心增加当前回合状态层，包含当前行动者、方向和当前颜色。
- 当前玩家/当前 AI 使用边框和局部色光强调，其他座位降低视觉权重。
- 特殊阶段使用不同状态样式：正常回合、摸牌、叠牌响应、+4 挑战、UNO 窗口、结算锁定。
- 事件日志和 AI 台词保留，但降低其对牌桌中心的争夺。
- 对手卡背数量变化只做一次短反馈，避免每次 render 触发动画重启。
- 牌堆数量、叠牌累计和方向箭头统一视觉语言。

建议优先使用现有 view.currentSeat、view.phase、view.table、事件队列和 data-seat，不扩展规则层字段。

### 4.4 V2-03：手牌与操作区

目标：让玩家在不同屏幕尺寸下都能快速找到可出牌和下一步动作。

工作内容：

- 保留“点击手牌出牌”的现有交互，不恢复重复的出牌按钮。
- 重新区分合法牌、不可用牌、刚摸到的牌和当前聚焦牌。
- 桌面端保持手牌横向展开；手牌过多时明确滚动边界和当前牌焦点。
- 移动端将操作区稳定在手牌下方，避免按钮随牌数或提示文字跳动。
- 摸牌、结束回合、叠牌弃权、挑战、抓 UNO、UNO! 等动作按当前阶段排序。
- UNO 窗口继续使用倒计时条，但将倒计时、按钮和状态提示作为一个整体处理。
- 触控目标保持至少 44px，键盘焦点和 disabled 状态清晰可见。

### 4.5 V2-04：大厅与联机入口

目标：让玩家更快开始单机游戏，同时保留局域网能力。

工作内容：

- 设定“开始游戏”为唯一主操作，设置、战绩和联机入口降为次级操作。
- 对战人数、AI 难度、AI 模式、规则选项使用一致的选择控件样式。
- 局域网入口使用可折叠的次级区块，创建房间、加入房间和附近房间保持清晰分层。
- 房间页强化房间码、玩家列表、房主状态和开始条件。
- 移动端优先保证配置流程可滚动、输入框不被键盘遮挡、主要按钮可见。
- 保留现有 START_GAME、房间创建、加入和退出动作契约。

### 4.6 V2-05：结算页与信息总结

目标：让结算页先给结论，再提供统计。

工作内容：

- 顶部强化赢家/平局、原因、回合数和用时。
- 总览数字保留动作、出牌、摸牌、叠牌、UNO、挑战等现有数据。
- 图表继续使用 result.players[] 和全局统计，不在 UI 重新计算规则或分数。
- 玩家结算行强化“出完手牌”“手牌最少获胜”和剩余牌视觉反馈。
- 移动端将图表改为单列，图例和数值必须在窄屏内完整显示。
- “再来一局”和“回大厅”保持固定、易找到的位置。

### 4.7 V2-06：动效、无障碍与响应式收口

目标：把视觉升级收敛成可发布版本。

工作内容：

- 统一进入、退出、状态变化、牌数变化、UNO、结算的动效时长和缓动。
- 审查所有颜色对比度、键盘路径、焦点样式、aria-live、aria-label 和 aria-hidden。
- 验证 prefers-reduced-motion、动画关闭、低性能设备和触控设备。
- 验证 2/4/10 人、单机/联机、不同视角座位和 420/760/1024/1440 宽度。
- 保持现有 60 FPS 目标，避免为每张对手卡背引入不必要的图片节点或持续动画。

### 4.8 V2-07：发布与回归

目标：以 UI 版本正式发布 v2.0.0。

工作内容：

- 补充 verify:ui 的 M13 和 v2.0 状态断言。
- 补充 verify:online 的对手卡背、视角隔离和表情气泡不遮挡检查。
- 运行 npm test、npm run typecheck、npm run lint、npm run verify:ui、npm run verify:online。
- 桌面版至少执行启动、窗口尺寸、安装包静态资源和 UI 回归检查；真实 GUI 仍按当前桌面验收条件执行。
- 更新 CHANGELOG.md、版本说明、截图和 UI 文档。
- 以独立提交或清晰的变更边界发布 v2.0.0，不混入 M11/M12 或规则改动。

## 7. 验收标准

### 7.1 功能与状态

- 2、4、10 人对局均能正确显示对手卡背数量。
- 0/1/2/3/4/5/6+ 张手牌映射稳定，精确牌数文字保持正确。
- 视角座位变化后，自己的座位不会被渲染为对手。
- M13 卡背不泄露手牌牌面，不改变公开视图和联机隔离。
- 当前回合、AI 思考、叠牌、+4 挑战、UNO、结算状态均有明确视觉差异。
- 重渲染、台词 TTL、表情气泡、事件队列、弹窗状态不回归。

### 7.2 响应式

- 1440×900：牌桌中心、对手座位、手牌和操作区有稳定层级。
- 1024×768：10 人局不出现座位框重叠或牌桌溢出。
- 760×900：对手网格、中心牌堆、手牌和操作区均可操作。
- 420×844：主要动作、当前颜色、精确牌数和结束路径完整可见。
- 横向滚动只出现在设计允许的手牌区域，不出现在整个页面。

### 7.3 可访问性与性能

- 键盘可到达所有主要按钮、选择项和弹窗动作。
- aria-live 只播报必要状态，不重复播报装饰性卡背。
- 卡背堆使用 aria-hidden=\"true\"，对手座位提供准确文本标签。
- reduced motion 和动画关闭下没有持续闪烁或自动位移。
- 视觉升级不降低现有 60 FPS 目标，不为对手卡背引入大规模 DOM 或持续布局抖动。

### 7.4 工程质量

- npm test 通过。
- npm run typecheck 通过。
- npm run lint 通过。
- npm run verify:ui 通过。
- npm run verify:online 通过。
- 桌面版静态资源、启动流程和现有安装包边界不回归。

## 8. 风险与处理

| 风险 | 处理策略 |
| --- | --- |
| M13 实际代码与文档状态不一致 | V2-00 先做状态核对，统一文档、实现和截图 |
| 对手卡背遮挡头像、UNO 或上一张牌 | MVP 封顶 5 张，固定左下角安全区，420 宽度可隐藏装饰卡背 |
| 10 人局信息过密 | 使用相对视角布局，降低卡背尺寸，保留精确数字文字 |
| 当前回合强调过强导致牌桌闪烁 | 使用边框和局部光效，限制动画次数和持续时间 |
| UI 重渲染打断表情、台词或事件动画 | 保持现有局部清理机制，新增状态动画使用 diff 或一次性 class |
| 视觉改造混入规则改动 | 每个提交限制在 UI、验证和文档边界内 |
| 移动端只按浏览器模拟验证 | 先完成 420/760 视口，再安排真实触控和键盘检查 |
| 过早引入主题/皮肤设置 | v2.0.0 只建立 token，不开放用户主题配置 |

## 9. v2.0.0 之后的候选项

以下内容不属于 v2.0.0 发布范围：

- M13 完整 N 张、右侧卡背、卡背皮肤和显示密度设置。
- 跨网公网联机、固定公网服务、账号和排行榜。
- 联机智谱在线决策、对局快照和跨设备恢复。
- 复杂牌面飞行、完整发牌动画和连续粒子背景。
- 自定义表情、聊天、表情历史和玩家人设系统。
- 规则变体编辑器和完整主题市场。

这些能力需要单独评估数据模型、联机安全、性能和产品范围，不作为 v2.0.0 的隐含承诺。

## 10. 完成定义

当以下条件全部满足时，v2.0.0 才视为完成：

1. M13 对手手牌可视化完成并通过 2/4/10 人、单机/联机和移动端验收。
2. 当前回合、特殊阶段和主要动作在桌面与移动端都有清晰视觉层级。
3. 大厅、牌桌、手牌、结算四个主要流程使用统一 token 和交互状态。
4. 动画关闭、reduced motion、键盘焦点、视图隔离和表情/台词生命周期没有回归。
5. 现有测试与 UI 验收全部通过，桌面版现有启动和打包边界不受影响。
6. 版本文档、截图、变更日志和开发进度状态已同步。
