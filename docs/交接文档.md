## 7. 关键坑位

- `unoWindow.canCatch` 语义是「可被抓的目标」（开窗时 = 窗口主人），不是抓人者名单。
- 联机 `config.humanSeat = -1`；单机为 0。判断「我」必须用视角座位，不能写死 0。
- 联机每个座位 `isHuman` 可能为 true，对手框要用 `seat !== viewer` 过滤，不能靠 `!isHuman`。
- `drawnThisTurn` 只在 `state.currentSeat === seat` 时下发；他人 DRAW 事件 `cards=[]`。
- 开局座位随机；起手 Skip/Reverse/+2 由首位玩家承受，手牌可能 >7，断言别写死 7。
- vitest 默认超时 5000ms；WS 集成测试内部等待超过 5s 必须显式传 `{ timeout }`。
- `verify:ui` 端口 9333，`verify:online` 端口 9334；后台标签页定时器可能被节流，冷却断言用轮询。
- 局域网房间只在服务进程内存；IP 变化以 `/api/health` 为准；防火墙规则 `UNO-Local-3000`。
- 启动脚本不要写 PowerShell 自提权/隐藏窗口：已被火绒误报为 `PS.NetLoader`。保持纯 cmd。
- 卡面解码偶发时序 flaky（verify:ui 102/103），复跑即可；不要因此改业务代码。
- 桌面版 `main.ts` 必须先 `import './environment.ts'` 再导入 server；config 在模块加载时读路径环境变量。
- 桌面服务 `listen(0)` 后 `/api/health` 必须用实际端口；`createUnoServer` 已默认读取 `server.address()`。
- Electron 二进制首次运行才下载；本机 GitHub 直连 TLS 校验失败，可用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 后执行 `node node_modules/electron/install.js`。
- 本机沙箱内真实 Electron GUI 会以 `0x80000003` / `0xC0000005` 退出，桌面窗口验收需在用户桌面会话执行。
- 标准 electron-builder NSIS 会在打包阶段**执行刚生成的中间安装器**来产出卸载器，本机沙箱阻断新 exe 进程会直接失败；本项目改为 `nsis.script: installer.nsi` + 原生 `WriteUninstaller`（`apps/desktop/build/installer.nsi`），打包只跑 `makensis`。不要删掉该脚本改回默认。
- electron-builder 要求 `electron` 写**精确版本**（本项目固定 `44.9.1`），用 `^` 会报 "version is a range"；打包需设 `ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR` 走 npmmirror。
- `apps/desktop/release/` 是打包产物，已 gitignore，eslint 也已忽略；`apps/desktop/build/`（图标 + `installer.nsi`）要入库。
- `safeStorage` 只能在 `app.whenReady()` 之后使用；`main.ts` 的 `bootstrap()` 先 `loadStoredApiKey()` 再 `startUnoServer()`，顺序不要反。
- 智谱 Key 的运行时来源统一走 `apps/server/src/ai-key.ts`（自填 > `.env`）；`zhipuClient.isConfigured` 是 getter，不要改回构造时快照，否则保存 Key 后需重启。
- Key 只允许经 `window.unoDesktop.aiKey` 的「状态/保存/清除」进出，IPC 永不回传明文；不要把 Key 写进 `/api/config`、日志或设置页 DOM。
- `verify:ui` 在浏览器模式断言设置页**不显示**桌面 Key 区域；桌面专属 UI（Key、手动主机、附近房间）一律用 `window.unoDesktop` 分流。
- UDP 发现固定端口 `41234`、广播间隔 2 秒、缓存 TTL 7 秒；只广播 `lobby` 房间，开局后自动从列表消失；同网段/防火墙/AP 隔离会影响发现，手动 `IP:端口` 是兜底路径。
- 远程联机的目标主机必须写入 `joined.host`（`host:port`）；断线重连和刷新恢复都依赖它，不能只存本机 `location.host`。
- 发现结果只经 `uno:discovery-list/find` 只读 IPC 返回；`findRoom` 先匹配本机内嵌房间，再查 UDP 缓存；同码多个兼容主机才显示选择器。
- 桌面发现 UI 的 `listRooms` 轮询失败必须静默，不能阻断浏览器/单机模式；`window.unoDesktop.discovery` 不存在时所有新入口保持隐藏。
- 房主迁移只由服务端 `RoomManager.promoteHost()` 决定：房主断线/离开→下一位**在线**玩家；原房主重连不夺回；全员断线时保留原房主。`hostSeat` 是唯一权威，客户端只根据房间广播提示，不要本地推断。
- `server-closing` 是只增消息，旧客户端会忽略；桌面主进程 `stopUnoServer()` 必须先 `notifyShutdown()` 并等约 150ms 再断开，否则远程客户端会走 3 次重连。强杀进程不会走该路径。
- 客户端 WS 握手超时为 8 秒；旧 socket 的 handler 必须用 `socket === ws` 守卫，否则重连时旧连接的 close 会误触发新一轮重连。
- `verify:desktop` 在本机沙箱会因 Electron GUI 以 `0x80000003` 退出而 SKIP；不要把它当成通过。真机执行时可设 `UNO_REQUIRE_DESKTOP=1` 强制失败退出。
- `apps/desktop/release/UNO-Setup-1.3.0.exe`（2026-10-21 13:43，SHA256 `B14FBB83…3B61A6E`）已包含 M10-05/06；`release/win-unpacked` 可能仍是 12:57 的旧解包目录，验收以安装包为准。
