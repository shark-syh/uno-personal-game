## 4. 红线与硬约定

1. **摸牌**：主动摸牌逐张、摸到可出为止；只能打刚摸的牌或结束回合；效果摸牌可一次多张。
2. **UNO**：单击即喊，无二次确认；最后一张出完直接赢，罚 2 张；窗口 10/8/6/4 秒（休闲/简单/真实/骨灰级），裁决仍在引擎/服务端。
3. **UNO 窗口按钮**：窗口主人只见 `CALL_UNO`，其他座位只见 `CATCH_UNO`。
4. **结算**：无算分，只保留结算与操作统计图表；本地战绩仅 `games/wins`。
5. **挑战展示**：仅人类挑战 AI 时展示对方手牌；AI 挑战人类不泄露牌面。
6. **视图隔离**：`drawnThisTurn` 只发摸牌者；他人 `DRAW` 事件 `cards=[]`；联机按座位脱敏。
7. **联机**：服务端权威；`config.humanSeat=-1` 时用视角座位判断「我」。
8. **UI 契约**：`window.UnoApp` 五个 API 与 DOM 锚点只增不改；出牌只点手牌。
9. **v2 边界**：不改 `packages/game-core`、`packages/ai`、GameView/UiAction/事件类型、WebSocket 协议与桌面壳。
10. **不做**：台词库、自定义表情/持久化/文字聊天、对局快照、跨网公网联机。
11. **圆角硬性规定（2026-11-07 用户指令，优先级最高）**：图标、卡片、面板、按钮、输入框、弹窗、牌面裁切等**一切 UI 圆角必须使用连续曲率**（squircle / 超椭圆），**禁止 `border-radius: Npx` 的普通圆弧**（直线与圆弧交界处曲率突变）。统一资源 `apps/web/assets/squircle.svg`（n=5）、全局 token `--ui-squircle`（`styles/tokens.css`），标准写法与滤镜/遮罩顺序见 [`UI优化方案-待开发.md`](./UI优化方案-待开发.md) §0。新增**带圆角** UI 一律先套遮罩再谈圆角，旧圆角元素随 U4 逐步替换。**例外（2026-11-07 用户追加拍板，优先级最高）**：「数据显示的卡片不用做圆角」→ 右栏 `.status-card`（CURRENT PRESSURE / RECENT EVENTS）与 `.rail-turn-chip`（TURN 标签）一律 `border-radius: 0` + 1px 实线边框、不套 squircle 遮罩，U4 不得改回；直角面板不属本条约束范围。
12. **汇报 / 自检 / 提交硬性规定（2026-11-07 用户指令，优先级最高）**：① 每次开发完输出**只包含三段**——「开发了什么 / 能实现什么样的效果 / 还剩什么」，不得有第四段；② 每次修改文件后**自行验证无 bug**（lint / typecheck / test / verify / 链接与产物核对，按范围实跑）才汇报，验证结果不单独成段；③ 用户批准下一步开发后**先自动 `git commit` + 打 tag，再开始下一步开发**，不做 push。首次批准前先按逻辑分组提交历史存量改动并打 `u0-baseline`。全文见 [`开发约定.md`](./开发约定.md) §7；本条覆盖旧四段式汇报与「汇报里给测试步骤」的输出形式。
