## 2. 红线与硬约定（后续开发者请勿改回）

1. **摸牌**：主动摸牌**点一次摸一张，摸到能打出的牌才停**（2026-10-19 用户反馈）；而 +2/+4 效果摸牌、UNO 罚款等「效果摸牌」仍可一次多张，DRAW 事件带 `count`。
2. **UNO**：单击一次立即喊出（无二次确认弹窗）；UNO 窗口 **4 秒** + 按钮底部倒计时条。
3. **AI 思考延迟随机化**：约 0.8~1.7 倍抖动、下限 300ms；智谱「思考中」最短展示 500ms；智谱决策在动画播放期间预取。
4. **结算无任何分数 / 趣味分 / 算分口径**：结算页只保留最终结算 + 操作统计图表；本地战绩只写 `uno:stats` 的 games/wins。
5. **挑战手牌展示仅当挑战者是人类时可见**（AI 挑战人类只提示，不展示牌面）。
6. **动效 / 音效可关闭**；关闭动画或 reduced-motion 时不创建任何动效元素。
7. **大厅无用户名输入**（人类固定「你」）。
8. **M6-03 台词库 / 人设、M6-04 战绩统计**：用户明确指示不做；**M6-06 对局快照恢复**：暂不做（P2）。

## 3. M7 记录

### 3.1 M7-01 E2E 固化
`verify:ui`（无头 Chrome + CDP，零第三方依赖）确立为项目唯一正式 E2E，替代原计划的 Playwright。新增 `docs/E2E测试指南.md`；CI 新增 `browser-acceptance` job（ubuntu-latest + Node 22：`npm ci` → 启服 → `verify:ui` → 上传报告 artifact）。

### 3.2 M7-02 性能检查
新增 `scripts/perf-check.mjs` + `npm run perf`。结果：首屏 FCP 176ms、平均 FPS 60（满帧）、JS 堆内存平稳；本地 AI 无网络请求，智谱耗时由状态栏 title 展示。结论达标。

### 3.3 M7-03 `npm start` 单进程可用
`prestart` 自动构建浏览器引擎包 → `tsx src/index.ts` 启动，用户只需一条 `npm start`；`/api/health` 返回 `{"status":"ok","version":"1.0.0"}`；控制台 0 报错（verify:ui 断言）。

### 3.4 M7-04 README 发布内容补全
README 覆盖安装、配置、运行、设置项、常用命令、测试与质量、架构、目录、版本、文档、FAQ、已知限制与路线图、免责声明；本轮补 `npm run perf` 行，`verify:ui` 由 102 更新为 103。

### 3.5 三项用户反馈修复（M7 期间）

- **修复① 本地 AI 思考延迟随机化**（2026-10-18）：固定值改为「难度基准 × 速度档 × 0.8~1.7 随机系数」，下限由 120ms 提到 300ms；`?test=1` 仍固定 15ms。
- **修复② UNO 窗口延长到 4s + 倒计时条**（2026-10-19）：`UNO_WINDOW_MS` 由 2500 → 4000；`CALL_UNO` 按钮底部追加 4s 倒计时条（动画关闭 / reduced-motion 时不创建）；「抓他！」窗口同步变长到 4s。
- **修复③ 摸牌改为「点一次摸一张」**（2026-10-19）：引擎一次 DRAW 只摸 1 张（可出则锁定 `drawnThisTurn`、按钮消失，不可出则按钮保留可继续摸）；AI 逐张摸后统一播动画；DRAW hint 文案同步。

## 4. M8 记录（2026-10-19 开始）

### 4.1 M8-01 房间与 WebSocket 基础设施 ✅
服务端引入 `ws`（`@uno/server` 新增依赖 `@uno/game-core` / `ws`）；`src/net/protocol.ts`（消息定义 + 严格入参校验）、`src/net/rooms.ts`（房间码 6 位、创建/加入/座位分配/房主开始/离开与断线标记）、`src/net/wsServer.ts`（连接绑定 roomCode+seat+token）、`src/server.ts`（app+http+ws 装配，`/ws` 路径）。客户端大厅新增「局域网联机」区块（显示名可选默认「你」、创建房间 / 输码加入）与房间面板（房间码、座位列表、房主开始按钮）。

### 4.2 M8-02 服务端权威游戏循环 ✅
房间持有唯一 `GameState`（`createInitialGame`，所有座位 isHuman=true、名字取房间显示名）；上行动作先过座位权限校验（当前行动座位 / UNO 窗口喊抓按窗口状态判定），再交 `applyAction` 裁决；每次应用后按座位 `getGameView(state, seat)` 各发各的脱敏视图（复用 `sanitizeEventsForSeat`）。回合推进、UNO 窗口、挑战窗口全部由引擎状态机裁决。客户端最小联机路径：动作上行 WS、渲染服务端视图（垂直切片「双客户端同局」，细节打磨归 M8-03）。
