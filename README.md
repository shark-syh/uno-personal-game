## 这游戏到底想做什么

它不是「把 UNO 搬到电脑上」就完事了。更想解决的，是突然想打一局、却凑不到人的那种空落落的感觉——所以这里没有账号、没有匹配、没有每日任务，打开就能坐下一桌，打完就走。

另一半心思花在「看得清」上。我们叫它 **Orbit Control**：中间一张椭圆牌桌，左边一条回合轨，右边一块常驻数据栏。第几回合、谁还剩几张、牌堆快见底没、刚才谁干了什么、所有人的手牌怎么一点点变少，全都同时摆在眼前，不用翻页、不用猜。

原来的荧光绿牌桌讲「**PLAY WITH INTENT.**（带着想法出牌）」。这次加进来的友尽版讲另一句话：「**NO ONE LEAVES.**（谁也别想走）」——同一套三屏界面，换成 168 张牌、25 张淘汰线和血红主题，气质就完全反过来了。

有三件我们挺坚持的小事：

- **不凑人**：2~10 个座位，除了你都可以是 AI。断网、没 Key、没额度，一样能把一局打完。
- **不记分**：赢了就是赢了。结算页没有「本局得分」，只有这一局发生过什么。
- **不蒙牌**：信息摊在一屏里，出哪张是你自己判断的，不是靠蒙。

**一局的路径**：`01 大厅`（选人数 / 难度 / 玩法模式）→ `02 牌桌`（一屏三栏 · 出牌 / 摸牌 / 叠牌）→ `03 结算`（谁赢了 + 这一局发生了什么）↩ 点「再来一局」回到大厅。三屏的细节往下翻。

几个刻意定下来的细节：

- **只在大厅显示**。进了对局 / 结算屏自动隐藏，不会压在手牌区上；对局中改档只影响**下一局**，不动正在打的那局。

- **主题按需加载**。默认大厅根本不加载友尽样式表，第一次点到 / 悬停友尽档才动态插入 `mercy-mode.css`；切换时走 90 ms 淡入淡出，`prefers-reduced-motion` 下直接切，不做动画。

- **一切圆角仍是连续曲率 squircle**，右栏两块数据卡按老规矩保持直角。

## 友尽模式：牌堆不会放过任何人

这套规则来自 UNO Show 'Em No Mercy，按 `docs/三模式升级-友尽模式规则契约.md` 落地。核心就一句：**手牌越多越危险，到 25 张直接出局**——被淘汰者的手牌先搁置，牌堆耗尽重洗时再放回，回合自动越过他；全场只剩一人时，他以 `last-survivor` 获胜。

**牌堆构成**（168 张）：

| 类别 | 组成 | 张数 |
| --- | --- | --- |
| 数字牌 | 0~9 各色 2 张 × 4 色 | 80 |
| 彩色功能牌 | Skip / Reverse / Draw 2 / Discard All 各色 3 张 × 4 色 | 48 |
| 彩色功能牌 | Draw 4 / Skip Everyone 各色 2 张 × 4 色 | 16 |
| 万能牌 | 反转 +4 ×8、颜色轮盘 ×8、+6 ×4、+10 ×4 | 24 |

**新增的 7 种牌型**：彩色 `Draw 4`、`Skip Everyone`、`Discard All`，以及四张随时可出、不受「手里没有当前颜色牌」限制也不可质疑的万能牌 `Wild Draw 6` / `Wild Draw 10` / `Wild Reverse Draw 4` / `Wild Color Roulette`。

**数字牌里藏了两把刀**：打出 **7** 必须与任意一位仍在局中的玩家交换整手牌（强制，弹窗选目标）；打出 **0** 则全体按当前方向把手牌传给下一位（只旋转活跃座位）。

其余效果逐张看：

| 牌 | 效果 |
| --- | --- |
| Skip Everyone | 其余玩家全部跳过，自己立即再来一回合，方向不变 |
| Discard All | 弃掉手里所有同色牌压在该牌下方，顶牌与颜色不变，可一次清空直接获胜 |
| Wild Draw 6 / 10 | 出牌者选色，下家抽 6 / 10 并跳过；+10 是叠链上限 |
| Wild Reverse Draw 4 | 先反转方向 → 新方向下家抽 4 → 出牌者选色；2 人局变成自己抽 4，可立刻叠罚牌回敬 |
| Wild Color Roulette | **下家**选色 → 逐张翻抽直到抽到该色（Wild 不计）→ 全部进手牌并被跳过；双堆耗尽时兜底停止并跳过 |

**叠链**按官方口径：被 +2 / +4 / +6 / +10 / 反转 +4 指到时，只能打出**等值或更高**的罚牌把累计额推给下家，Skip / Reverse 不能叠；第一个接不住的人一次性抽走累计总额并被跳过。右栏会实时显示累计需摸张数。换手和轮盘各有一个专属弹窗，不会挤在 44px 的细轨里；被淘汰的座位灰显去饱和。

界面上，友尽对局屏从牌桌径向渐变、对手卡描边、右栏数据卡 / 折线图 / 阶段标签到手牌坞，全部换成暗红系；叠链累计、淘汰状态、换手 / 轮盘待选座位跟着引擎的 `mercy` 摘要走。联机同样支持：房主在大厅选好 mode，`start-game` 带过去，服务端按座位脱敏后再广播。

> **关于卡面**：友尽 B 版 68 张 webp 只用于作者本人本机学习演示，**不进仓库、不进 exe、不进 Release**（`.gitignore` 与 `electron-builder.yml` 双重排除）。本机把素材放到 `apps/web/cards-mercy/` 就会自动启用；缺素材时 `renderCard()` 降级成色块 + 文字牌面，规则照常跑。完整权限申明见文末与 `research/open-mercy/README-来源与裁剪.md` §6.5。

## 基础模式：让牌局上头的三条规矩

**宽松叠牌：数字会滚雪球。** +2 压 +2、+4 压 +2，反过来也行，颜色先放一边。链子越接越长，累计摸牌数一直涨，直到有人认怂，把那一摞一次性摸走。胜负常常在这一瞬间翻过来。

<p align="center">
  <img src="docs/images/v221-stack-10p.webp" width="820" alt="10 人桌的叠牌链">
</p>

<p align="center"><em>10 人桌也不糊：桌上写着「累计需摸 8 张」，右栏折线照常跑，每个座位都还在自己的位置上。</em></p>

**摸到能打为止。** 主动摸牌不是摸一张就停——会一直摸到摸出一张能打的牌，中途摸到的都留在手里；这一张要么打出去，要么结束回合。官方是摸 1 张，这里让牌局变长了一点，也多了一点「下一张会不会就是它」的期待。

**+4 挑战：可以赌一把。** 被 +4 指到的人，可以选择老实摸 4 张，也可以挑战、要求看对方手牌。人挑战 AI 时，对方的手牌会完整亮 2.6 秒；AI 挑战人时不泄露牌面，只留一句「XX 查看了你的手牌」。

## 一局牌是怎么走的

1. 在大厅挑好人数、难度、AI 模式，顺手在左下角选基础 / 友尽。
2. 点「开启对局」，发牌动画把牌送到每个座位，翻出一张起始牌。
3. 轮到你，能出的牌自动亮起，点一下就出；没得出了就点「摸牌」，或者按 <kbd>Space</kbd>。
4. 主动摸牌会一直摸到摸出一张能打的牌，中途摸到的都进手牌；这一张要么打出去，要么结束回合。
5. AI 会短暂想一下再出牌。接了智谱的话，它们偶尔冒一句台词，停 2.6 秒就散。
6. 友尽里还要盯着手牌数：一旦到 25 张就出局；换手 / 轮盘轮到你时，弹窗里选目标座位或颜色。
7. 有人打完手牌、牌堆见底，或只剩一位幸存者，这局就停。没有下一关，想再来一局点一下就行。

## 牌友不是木头人

AI 分四档：休闲、简单、真实、骨灰级。档位不只是「多想一会儿」，它真的会改记牌、留牌、叠不叠、挑不挑战、抓不抓 UNO 的选择。同一手牌交给不同档位，下一步常常完全不一样。友尽里补了换手目标（按对方手牌数启发）与轮盘选色两类新动作的候选。

本地 AI 完全离线：先把能做的动作列成候选，逐张打分，记住已经出现过的牌，再从合法动作里挑一个，通常只要几毫秒。接了智谱之后多一步：把公开信息和自己的手牌整理成候选交给模型选，回来还得过一遍本地合法性校验。模型选错、超时、额度用完，都自动退回本地 AI，牌局不会卡在那儿等它。

| 轮到 AI 时 | 决策路径 | 出问题时 |
| --- | --- | --- |
| 本地 / 自动且无 Key | 本地启发式：列出候选 → 逐张打分 → 记牌 → 挑一个 | — |
| 智谱 | 服务端代理整理候选 → 模型选牌 → 本地合法性校验（合法 / 没超时 / 没限流） | 选错 / 超时 / 额度用完，自动退回本地 AI |

两条路最后都汇到**同一个出牌入口**，走同一条规则链，牌局不会卡在等待模型上。

在线决策会慢一些（思考型模型一次约 3~4 秒），所以下一步的请求会在上一步动画播放时就提前发出；动画放完，回答往往已经在路上。状态栏悬停能看到最近一次用的模型和耗时。想秒回，把 AI 模式切到「本地」就好。Key 只在服务端读，不会进前端代码；桌面版还可以在设置页自填，用 DPAPI 加密存起来。

## 背后是怎么跑起来的

一句话：**引擎是唯一的裁判，界面只负责把裁判说的话演出来。**

```text
[你的操作] 点一张手牌
   → UiAction
   → game-core: applyAction(state, action)
   → 新 state + events
        ├→ public-view（按座位脱敏）→ window.UnoApp.render（牌桌 / 右栏 / 手牌）
        └→ 事件队列（动效 + 音效）→ 上面同一个 render
[AI 的一步] AI 选好一步 → 同一个 UiAction 入口
```

拆开说，就是这么几件事：

1. **一个纯函数管全部规则。** `applyAction(state, action)` 吃进旧状态和一步动作，吐出新状态和一串事件（`packages/game-core`）。同一个 seed 加同一串动作，一定能复现同一局——所以 AI 自对弈能一口气跑 700 局专门找非法动作，友尽另跑 200 局查 168 张守恒。
2. **mode 是一条独立的轴。** `normalizeGameConfig({ mode: 'mercy' })` 把叠链锁成 `official`、关掉 `challengeWild4`；`GameView` 顶层带 `mode` 与 `mercy` 摘要（待换手 / 轮盘座位、搁置牌数、淘汰座位）、`players[].eliminated`、`table.stackTotal`。**classic 的 `playCard` 路径逐字未动**。
3. **每人只看到该看的。** `public-view.ts` 在状态出门前先脱敏：别人的手牌、牌面、+4 判定依据、挑战时才亮出的手牌，都按座位过滤掉。友尽新增的 8 类事件按定义字段显式重建，换手 / 传手后 `drawnThisTurn` 与基于它的 `PLAY_DRAWN` 动作都按座位剔除，杜绝牌面串座。联机时这一步由服务端做。
4. **界面是被事件推着走的。** 发牌、出牌、摸牌、跳过、反转、叠牌、挑战、UNO、洗牌、换手、传手、轮盘、淘汰……事件进同一个队列，一个播完再播下一个，播放时锁住输入。动效只改 `transform` 和 `opacity`，10 人桌也不会满天飞牌；队列结束，临时元素和定时器都清干净。
5. **声音是现算的。** 16 类事件音全部由 WebAudio 的振荡器和噪声合成，仓库里没有一个音频文件。浏览器不让自动播放，所以第一次点击 / 按键之后才解锁，也能单独关掉或调三档音量。
6. **联机时服务端说了算。** 房间状态在服务端内存里，客户端只发意图、收自己那份视图；掉线自动重连坐回原位，实在回不来由服务端 AI 顶着，房主走了自动移交给下一位。协议白名单补了 `SWAP_HANDS` / `CHOOSE_ROULETTE_COLOR`，`flip` 明确拒绝、不静默回退。

代码大致分成这几块：

```text
apps/web/              界面 · 原生 HTML/CSS/JS，零构建
  ├─ js/engine/        对局调度、AI 决策、UNO 窗口、台词、事件队列
  ├─ js/ui/            大厅 / 牌桌 / 手牌 / 结算渲染、模式切换器
  ├─ js/animation/     事件动效与串行队列
  ├─ js/audio/         WebAudio 合成音效
  ├─ styles/           tokens / layout / mode-switch / mercy-mode（按需加载）
  └─ js/vendor/        uno-engine.js（TS 引擎 + 本地 AI 的浏览器打包产物）
apps/server/           Express：静态托管 + 智谱代理 + /ws 联机房间
apps/desktop/          Electron：内嵌服务、UDP 房间发现、Key 安全存储、NSIS 安装包
packages/game-core/    纯函数规则引擎 + 公开视图 + 结算统计
packages/ai/           候选生成 / 特征评分 / 记牌 / 四档难度 / 自对弈
scripts/               自对弈、浏览器验收、性能检查、打包与卡面处理
docs/                  开发文档与本文截图
```

没有数据库、没有账号、没有遥测。设置和那点对局数 / 胜场，就放在浏览器 `localStorage` 里；模式偏好只活在内存里。

## 和朋友坐一桌

同一局域网里，一台电脑开服务（双击 `启动服务.bat`，或 `npm start`），其他设备打开它打印的局域网地址，输 6 位房间码就坐到同一张桌上。桌面版还会自动发现「附近房间」，点一下就能进；UDP 广播被防火墙挡了，也可以手填 `IP:端口`。

进房能改名，房主可以给空位补 0~9 个 AI——一个人也能先开一局。房主在大厅选的 mode 会随 `start-game` 带进房间，`rematch` 沿用；对局由服务端统一裁决，别人摸了几张能数、但看不到牌面；刷新页面会静默恢复，房主断线自动移交，一局结束点「再来一局」原班人马直接重开。等待和对局中还能发 12 个预置表情，气泡落在自己座位框下面，每座位连发 5 条后冷却 2 秒。

> 联机的 AI 固定用本地启发式（智谱在线决策还没接进联机）；房间只存在服务器进程内存里，服务重启就得重新开房；UDP 发现只管同一网段，不支持公网。

| 变量（`.env`） | 说明 | 默认 |
| --- | --- | --- |
| `ZHIPU_API_KEY` | [智谱开放平台](https://bigmodel.cn/usercenter/proj-mgmt/apikeys) 的 Key | 空（只用本地 AI） |
| `ZHIPU_MODEL` | 首选模型 | `glm-4.7-flash`（免费） |

设置项（音效、动画速度、AI 速度、自动喊 UNO、2 人规则、UNO 罚牌张数、牌堆耗尽策略等）存在 `localStorage` 的 `uno:settings` 里；规则项只对**之后新开**的对局生效。改了 `packages/game-core` 或 `packages/ai` 记得跑 `npm run build:web-engine`，改了静态资源 `Ctrl+F5` 强刷。

## 还有哪些小毛病

- **进阶（Flip）模式方案已写但暂缓**，第三档灰显禁用；B 版里也没有任何 Flip 卡面，真要做需要第三套素材。
- **公开 Release 仍停留在 v2.2.0**：v2.3.0 完整安装包是本机自用、按权限申明不外传，所以公开渠道暂时下载不到带友尽模式的新 exe；代码与界面版本号本身已统一到 2.3.0。
- 友尽的 B 版卡面不随仓库 / 公开渠道分发，公开配置打出的产物会显示文字牌面；本机自用完整包内含 68 张，仅本人非商业使用。
- 模式偏好只在当前页面会话有效，刷新回基础模式；对局中切换下一局才生效。
- 单机刷新会中断对局（还没做快照恢复）；联机房间在内存里，服务重启就没了。
- 联机 AI 固定本地启发式；UDP 发现只管同一网段，不支持公网。
- 移动端只是基础响应式，桌面才是主要场景；`verify:desktop` 在本机沙箱里会 SKIP，需真机验收。
- 智谱在线决策一次约 3~4 秒；规则设置只对新开的对局生效。
- 自对弈里「相邻难度胜率单调」是 classic 的遗留已知项（混战平均名次已单调；友尽胜负含规则性运气，不做该判定）。
- `verify:ui` 的矮屏折线图与 AI 台词 TTL 两处断言对时序敏感，连续复跑会偶发失败，单独复跑即回到 208/208。
- 安装包未做代码签名，桌面版的安装 / 卸载、双机 UDP 发现、DPAPI 还没在真实用户环境走一遍；CI 曾在本机 esbuild 权限下失败，需读日志定位。
- 没附开源许可证（个人学习项目），第三方素材来源见 [`research/README.md`](research/README.md)。
